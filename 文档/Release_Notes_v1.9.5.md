## 一、本次范围

## 二、更新摘要

### 修复（时间轴日期面板）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 切换年份后停在**无媒体的月份** | `firstPhotoMonthInYear` 按月格式键 `2024-11` 查询，而直方图桶键是**日**格式 `2024-11-03`，恒查不到 | 改为按日桶键前缀判定月份 |
| 跨年跳转停在错误位置 | `seekTo` 用「最旧已加载键 vs 目标键」比字典序推断「目标是否已加载」，切档重载期间该推断错误 → 提前退出 | 改为以「能否精确命中目标分组」为终止条件，未命中继续翻页 |
| 跳转请求被静默丢弃 | 档位守卫 `want !== dimension` 直接 `return`，无任何提示 | 改为上报降级事件；并在目标档位到位后自动补发 |
| 定位落点被浏览器 clamp | `offsets` 是理论累加值，与真实渲染高度差 2.4 倍（单测算 4420，实测对应 1845） | 改为逐屏下滚 + `getBoundingClientRect()` 实测定位 |

### 规范

- `文档/版本管理规范.md` 新增 **§7 交付前验证门禁**：功能未经多维度交叉验证不得进入验收；明确五类验证手段与如实交代要求。

### 测试

- 新增 `seekLocator.spec.js`（6 条）：定位算法纯逻辑验证（跨年命中、偏移精确、退化查找、年月档）。
- 新增 `seekLazyLoad.spec.js`（4 条）：懒加载场景下的定位行为。

全量 **225 条**通过，前端构建通过。

## 三、升级注意事项

- **纯替换产物即可**，无数据迁移、无配置变更、无 API 契约变更。
- 修复集中在 `useTimelineSeek.js` / `useCalendarMatrix.js`，均为前端内部逻辑，不影响后端与数据库。

## 四、遗留与已知限制

- 跳转落点**已确认目标日期进入视口**，但未逐像素校验其是否精确置顶；如需严格置顶可调 `scrollToTarget` 校正阈值。
- `scripts/deploy.sh` 只覆盖测试通道，正式通道 `latest` 的推送仍为手工，门禁尚未覆盖。
- 告警适配器待填写真实凭据（`OPS_WEBHOOK_URL` 或 `OPS_SMTP_*`），当前告警仅落本地文件。
