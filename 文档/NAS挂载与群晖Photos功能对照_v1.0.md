# NAS 映射目录管理 vs 群晖 Photos 套件：功能对照与设计差异（v1.0）

> 2026-09-25，Job000114 后随 R4 裁决产出（用户裁决：物理目录模式不立项，需要功能区别说明）。
> 场景：NAS 目录（已有照片视频）映射到 Docker 容器使用本系统，与群晖 Photos 套件的对照。

## 一、一句话总览

**群晖 Photos 是「装好即用」的封闭套件：应用与磁盘天生一体，装上就自动认识 NAS 里的照片。**
**Panomint 是「平台无关」的自托管系统：NAS 只提供一块盘（目录），应用住进 Docker，两者之间隔着一层挂载——所以多出一个「扫描导入」动作，换来的是不绑定任何品牌硬件。**

## 二、核心机制对照

| 维度 | 群晖 Photos 套件 | Panomint（Docker 部署） |
| --- | --- | --- |
| 运行位置 | 直接跑在 DSM 系统里，与 NAS 一体 | 跑在 Docker 容器里，与 NAS 解耦 |
| 认识已有照片 | **自动**：套件后台索引服务持续监控 photo 目录，新文件自动入库 | **两步**：①目录挂载进容器（bind mount）②「扫描导入」把文件写入媒体库（管理后台→存储→扫描导入，或设 `MEDIA_SCAN_ON_BOOT=1` 启动自动扫） |
| 上传照片去哪 | 写进 NAS 目录（File Station 可见） | **同样写回 NAS 目录**（`media/年/月/` 结构，宿主机实时可见，双向实证过） |
| 应用内「文件夹」 | 与 File Station 目录**一体**：建文件夹=建目录 | **纯虚拟分类**：只记录在数据库，不在磁盘建目录/改目录——磁盘结构始终保持你放进去的原样 |
| 相册 | 虚拟集合 | 虚拟集合（两者一致） |
| 平台绑定 | 仅群晖（DSM + 套件中心） | 任何 Linux/Docker/NAS（群晖、威联通、自组服务器、云主机均可） |
| 360° 全景 | 基本不支持 | 360° 照片/视频、陀螺仪跟随、VR 头追、自适应码率流媒体 |
| AI 能力 | 人物/地点/事物识别（部分机型才有） | 人脸识别（YuNet+SFace）、地理逆编码、语义搜索（CLIP 向量），全部本地算力、不依赖厂商云 |
| 地图 | 地点视图 | 全屏地图 + 时间轴联动 + 聚合/悬停预览 |
| 权限模型 | 用户个人空间 + 共享空间 | owner/admin/member/viewer 四级 + 细粒度权限点 + 免登分享链接 |
| 格式支持 | 套件版本决定 | 8 类白名单（jpg/jpeg/png/webp/insp/mp4/mov/insv/lrv），HEIC 等显式跳过 |
| 升级/迁移 | 跟 DSM/硬件走 | 数据库+媒体目录两大件，换机器搬目录即走 |

## 三、两个最容易被问「为什么不一样」的差异

### 差异 1：为什么群晖「自动识别」，Panomint 要「扫描导入」？

群晖 Photos 的索引服务和磁盘**同住 DSM**，天生看得到 photo 目录里的每一次变化，所以是自动的。

Panomint 跑在容器里，NAS 目录是**挂载进来的一块盘**：容器「看得到文件」和「系统认识这张照片」是两回事——必须由扫描动作把文件登记进媒体库（时间轴/搜索/相册全靠这张登记表）。这个动作现在是：

- **手动**：管理后台 → 存储 → 扫描导入（增量、哈希去重，可反复扫）；
- **自动**：compose 里加 `MEDIA_SCAN_ON_BOOT=1`，容器每次启动自动扫一遍。

代价是多一个开关动作；收益是**同一套系统今天跑群晖、明天搬Any Linux 服务器，媒体库原样跟走**。

### 差异 2：为什么应用里建「文件夹」，NAS 目录里不出现？

这是刻意的虚拟语义：磁盘目录结构是**你的资产原样**，应用不做写操作去重组它（除了上传的写入）。好处：

1. 不会因为应用操作误动磁盘上的真实文件；
2. 分类逻辑（文件夹/相册/标签/人物）都可以随时改、嵌套、叠加，不受磁盘树限制；
3. 网络挂载（WebDAV/SMB/NFS）目录同样适用——对远程存储做 mkdir 本是高风险且语义各异的操作。

需要「分类反映到磁盘」的场景，当前答案是：先在磁盘上按你想要的结构整理好，再扫描导入——应用按目录归属呈现。

## 四、给从群晖 Photos 迁移过来的用户的三句话

1. **照片搬进来后不会立刻出现**——去管理后台点一次「扫描导入」（或加启动自扫环境变量），这是和群晖最大的使用差异；
2. **应用里的文件夹 ≠ NAS 目录**——分类在应用内做，磁盘保持原样；
3. **上传的照片会真实写回 NAS 目录**——`media/年/月/` 下 File Station 直接可见，磁盘仍是唯一真源。
