## 2. 管理员权限校验逻辑（需求 1）

### 2.1 两层鉴权，两个时机

本功能有**两类入口**，鉴权模型刻意不同：

| 入口 | 谁在用 | 鉴权方式 | 失败响应 |
| --- | --- | --- | --- |
| 管理端点 `GET/POST /admin/debug/*` | 管理员浏览器（JWT 会话） | `auth.RequirePerm(store, "admin:system")` | 未登录 401；已登录无权限 **403 FORBIDDEN**（与全站 admin 端点一致） |
| 调试接入端点 `GET /debug/channel/:id`（WS upgrade） | 开发者机器上的 agent CLI | 密钥认证（§5.2），无会话概念 | 功能未开启 **404**（不暴露功能存在性）；密钥错误 **401**；已有一个连接 **409** |

**状态码口径说明**：本功能沿用代码库现行约定——admin 功能门禁走 RequirePerm 的 403（`middleware.go:42`）；「404 而非 403」红线适用于媒体/相册等资源存在性，调试接入端点采用「未开启=404」达到同等**不可探测**效果（外人无法区分"没有这功能"和"没开"）。

### 2.2 校验流程（管理端点，每次请求全量执行）

```
请求 → ① JWT 会话解析（无/坏 → 401）
      → ② 用户禁用检查（USER_DISABLED → 403）
      → ③ RequirePerm("admin:system")：角色直查 roles 表 OR user_permissions 用户级直查（Job000067 语义，立即生效）
      → ④ 权限通过 → 进入 handler
```

- **鉴权时机**：无缓存、无白名单，每次请求实时查库（用户级授权收回后下一次请求即失效）。
- **查看权限 = 开启权限**：设置页卡片可见性与 `GET /admin/debug/status` 同一把锁——无权限者前端不渲染入口、后端不给状态，**不存在"只读泄露"通道**。

### 2.3 越权访问防护清单

| 风险 | 防护 |
| --- | --- |
| 普通用户直接调管理端点 | RequirePerm 403；前端隐藏仅 UX 层，后端为准 |
| 低权限管理员被授予其他权限时顺带获得 | 不新增权限位，授权面不扩张 |
| 越权授予 admin:system | `PermCovered` 已防（只能授予自己已拥有的权限，Job000067） |
| agent 端点绕过管理鉴权 | 密钥即凭据；无会话、无 Cookie → 无 CSRF 面；Bearer 头不经 URL |
| 密钥爆破 | 256-bit 熵 + 专用限流桶 + 失败锁定（§6.5），暴力不可行 |
| 内网 CSRF/跨站 | JWT 走 Authorization 头非 Cookie（既有登录语义），跨站请求天然不带凭据 |

## 3. URL 与 key 生成规则（需求 2）

### 3.1 双段凭据模型（标识与秘密分离）

| 段 | 名称 | 角色 | 是否敏感 |
| --- | --- | --- | --- |
| URL 路径段 | `channel_id` | 通道标识，出现在 URL/日志/审计 | **不敏感**（单独知道无任何价值） |
| 密钥 | `access_key` | 认证凭据，仅在 enable/rotate 响应中明文出现一次 | **敏感**，库中只存摘要 |

### 3.2 生成规范

| 项 | 规范 | 理由 |
| --- | --- | --- |
| `channel_id` | `crypto/rand` 12 字节 → 24 位小写 hex；字符集 `[a-z0-9]` | 96-bit，全局单通道场景冲突概率可忽略；DB UNIQUE 兜底+冲突重试；hex 免 URL 编码 |
| `access_key` | `crypto/rand` 32 字节 → base64url（RFC 4648，无 padding）→ **43 字符**；字符集 `[A-Za-z0-9_-]` | 256-bit 熵，暴力空间 2^256；URL 安全免编码 |
| 随机源 | 强制 `crypto/rand`，**禁用 math/rand / 时间戳 / UUID** | CSPRNG 是底线；单测钉：1e4 次生成零重复且字符集合规 |
| 唯一性保证 | ① 256-bit 生日界：生成 1e9 个密钥冲突概率 < 1e-19；② `channel_id`、`key_digest` 双 UNIQUE 约束；③ INSERT 撞 UNIQUE 时重生成重试（≤3 次，再败 500） | 数学保证 + 工程兜底 |
| 存储形态 | `key_digest = lower(hex(sha256(access_key)))`，64 字符 | 与算力节点 `HashAgentToken` 同构；摘要比对用 `subtle.ConstantTimeCompare` 防时序侧信道 |

### 3.3 URL 形态

```
wss://<部署域名>/debug/channel/<channel_id>
```

- 仅 `wss://`（生产）；`DEBUG_ALLOW_INSECURE_WS=1`（envOn，默认关）才放行 `ws://` 供本机开发（§6.2）。
- 密钥**只走 `Authorization: Bearer <access_key>` 请求头**，不走 query string（防 access log 落盘泄露）；nginx/caddy 默认不记录自定义头，双重保险。

## 4. 有效期与失效机制（需求 3）

### 4.1 有效期设置

| 项 | 设计 |
| --- | --- |
| 默认 TTL | **24 小时**（附录 Q4 可裁决调整） |
| 可选档 | 开启接口收 `ttl_hours ∈ {1, 8, 24, 72}`，其余值 400；前端下拉四档 |
| 存储 | `expires_at = now() + ttl_hours`，TIMESTAMPTZ；开启响应与 status 端点均回显 |
| 展示 | 设置页卡片倒计时（秒级显示剩余时间，<30 分钟红色警示） |

### 4.2 失效条件全表（任一触发即失效）

| # | 条件 | 检测点 | 对存量连接的动作 |
| --- | --- | --- | --- |
| 1 | TTL 到期 | ① 连接握手时 ② 后台 reaper 每 5 分钟扫描 ③ 已连接期间随心跳复核 | WS 关闭码 **4001**，置 `enabled=false` |
| 2 | 手动关闭（§6.4） | 管理端点 | 关闭码 **4003** |
| 3 | 密钥重置（rotate，§6.3） | 管理端点 | 旧连接关闭码 **4004**（凭据已轮换），旧 `key_digest` 行内即换 |
| 4 | 连续认证失败 | 握手计数（§6.5） | 锁定期内一切握手 429 |
| 5 | 服务重启 | 进程死亡 | 连接自然断开（WS 层）；**通道状态在库中保留**，有效期内 agent 可重连 |
| 6 | 迁移回滚 | down 迁移 | 表 DROP，连接随进程重启断开 |

### 4.3 过期处理流程

```
reaper/握手检出 expires_at < now()
  → UPDATE debug_channel SET enabled=false WHERE id=true（幂等）
  → 若存在活动连接：WS Close(4001, "调试通道已过期")
  → 审计 debug.expired（actor=system）
  → 前端 status 轮询显示「已过期」，引导一键重新开启（= 全新 enable，见 §8.2）
```

**设计决策**：过期后通道回到「关闭」态而非悬挂「过期」态——状态机只有两态（开/关）+ 连接子态，「过期」由 `expires_at` 与审计表达，避免三态一致性负担。

## 5. 连接建立流程（需求 4）

### 5.1 完整时序

```
管理员                前端                 API 服务                agent CLI            DB/Valkey
  | 设置页开「远程调试」 |                     |                      |                    |
  |------------------->| POST /admin/debug/enable {ttl_hours:24}     |                    |
  |                    |-------------------->| ① RequirePerm         |                    |
  |                    |                     | ② advisory lock 742032|                    |
  |                    |                     | ③ 生成 channel_id+key |                    |
  |                    |                     | ④ UPSERT 行(摘要)     |---> debug_channel  |
  |                    |                     | ⑤ 审计 debug.enable   |---> audit          |
  |                    | 201 {url,key,expires_at}                    |                    |
  | 一次性展示+复制      |<--------------------|                      |                    |
  |                    |                     |                      | wss://.../channel/<id>
  |                    |                     |<===== WS upgrade =====| Authorization: Bearer <key>
  |                    |                     | ⑥ 404?401?409 前置矩阵 |                    |
  |                    |                     | ⑦ 升级 WSS，登记连接槽 |                    |
  |                    |                     |<===== {"seq":1,"type":"hello",...}           |
  |                    |                     |===== {"seq":1,"type":"hello_ack",server,proto_ver}
  |                    |                     |===== {"evt":1,"type":"snapshot",转码全景}     |
  |                    |                     |<===== {"seq":2,"type":"subscribe","payload":{"jobs":"*"}}|
  |                    |                     |===== 订阅确认，此后增量事件推送              |
  | 卡片显示「已连接」    |<== 5s 轮询 status ==| 心跳: WS ping 30s       |                    |
```

### 5.2 握手与认证步骤（服务器侧，upgrade 前完成）

| 步骤 | 检查 | 失败响应 |
| --- | --- | --- |
| 1 | 路径参数 `channel_id` 格式（`^[a-f0-9]{24}$`） | 400 |
| 2 | `debug_channel` 行存在且 `enabled=true` | **404**（未开启/已过期/不存在一视同仁，不可探测） |
| 3 | 连接槽空闲（进程内原子标志，单连接策略 §8.4） | **409** `DEBUG_ALREADY_CONNECTED` |
| 4 | `Authorization: Bearer` 头存在且形态合规 | 401 |
| 5 | 失败锁定检查（§6.5） | 429 |
| 6 | `sha256(key)` hex → 按 `key_digest` 查行 → `subtle.ConstantTimeCompare` + `expires_at > now()` | 401 `DEBUG_AUTH_FAILED` + 失败计数 +1 |
| 7 | 全程 HTTPS/WSS（r.TLS != nil 或 insecure 开关） | 426 |
| 8 | 通过 → Upgrade → 登记连接槽、更新 `last_connect_at/last_connect_ip` → 审计 debug.agent_connect | — |

### 5.3 WS 库选型（附录 Q2）

| 候选 | 许可 | 理由 |
| --- | --- | --- |
| **github.com/coder/websocket**（推荐） | MIT | context 一等公民（取消/超时天然正确）；并发读写在文档层约束清晰；活跃维护；无 cgo |
| github.com/gorilla/websocket | BSD-2 | 事实标准、资料多；但 API 易踩并发误用（本项目并发纪律成本高） |

### 5.4 消息协议（JSON 信封）

| 方向 | type | payload 要点 | 说明 |
| --- | --- | --- | --- |
| agent→srv | `hello` | `agent_version`, `nonce` | 服务端回 `hello_ack`（server 版本、协议版本） |
| agent→srv | `snapshot` | — | 全量转码现状：活动任务（含进度%）、队列深度（Valkey `LLEN q:transcode:*`）、worker 最近心跳 |
| agent→srv | `subscribe` / `unsubscribe` | `jobs: "*"` 或 `[job_id]` | 订阅任务事件流 |
| agent→srv | `job.pause` / `job.resume` / `job.cancel` | `job_id`（UUID 格式校验） | **底层绑定产品既有转码控制操作**；每条单独审计（§7.2） |
| agent→srv | `job.log.tail` | `job_id`, `lines ≤ 500` | 有界日志尾拉取；不提供 follow 长挂（防通道被日志占满） |
| agent→srv | `queue.stats` | — | 队列深度/消费速率 |
| agent→srv | `ping` | — | 应用层心跳（与 WS 协议 ping 并存） |
| srv→agent | `result` / `error` | 对应 `seq`；error 带机器可读 code | 命令应答，30s 超时 |
| srv→agent | `job.progress` / `job.state` | job_id、状态、进度、时间戳 | 订阅推送（evt 自增序号） |

### 5.5 部署集成点（nginx 两组前缀红线 + WS Upgrade）

- `debug` 加入 nginx 第 2 组纯 API 前缀正则（漏配 → upgrade 请求被 nginx 405 或拿回 index.html，坑位 20 同款）。
- WS 需要 Upgrade 头：`proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_read_timeout 3600s;`——当前 nginx conf 无 WS 先例（算力 agent 是轮询），属**新增配置**，随 web 镜像重建生效（Dockerfile 内嵌 conf 需单独 SFTP，坑位 12）。Caddy 反代对 WS 透明，无需特殊配置。

## 6. 安全控制（需求 5）

### 6.1 密钥生成

`crypto/rand` 32 字节（§3.2）；生成函数独立成包级纯函数便于单测穷举（字符集/长度/1e4 次零重复）。

### 6.2 传输安全

| 项 | 规则 |
| --- | --- |
| 生产 | 仅 WSS；`r.TLS == nil` 且未开 `DEBUG_ALLOW_INSECURE_WS` → 426 Upgrade Required |
| 开发例外 | `DEBUG_ALLOW_INSECURE_WS`（envOn 语义：显式 1/true/on 才开，默认关），仅允许 127.0.0.1 来源——**不写入任何默认配置/compose**（算力红线同款纪律） |
| 密钥载体 | 仅 `Authorization` 头；禁止 query/cookie/URL fragment；agent CLI 参数支持 `--key-file`（防进程列表泄露） |

### 6.3 泄露后的吊销与重置

```
设置页「重置密钥」→ POST /admin/debug/rotate（RequirePerm）
  → 事务内：生成新 channel_id+key，替换 key_digest/expires_at
  → 踢除活动连接 WS Close(4004)
  → 审计 debug.rotate（旧 channel_id 指纹+新 channel_id 指纹，明钥不落审计）
  → 响应 200 回新 {url, key, expires_at}（新密钥同样仅展示一次）
```

旧密钥在 UPDATE 提交瞬间即失效（查摘要对不上）；已泄露密钥的重放只会在审计留 `debug.auth_fail`。

### 6.4 手动关闭

`POST /admin/debug/disable`（幂等，未开启也 204）→ 置 `enabled=false` → 踢连接 Close(4003) → 审计。**关闭不清行**：`channel_id/key_digest` 保留至下次 enable 覆盖（UPSERT），保证 status 端点总能回答"现在没开"。

### 6.5 限流与失败锁定

| 控制 | 参数 | 实现 |
| --- | --- | --- |
| 握手专用令牌桶 | 突发 10、持续 0.2/s/IP | 复用 `queue.RateLimiter`，键 `rl:debug:hs:<ip>`——**与全站 60 桶完全隔离** |
| 认证失败计数 | 5 次/10 分钟 | Valkey 键 `rl:debug:fail:<ip>` INCR+EXPIRE；触顶锁 15 分钟 |
| Valkey 不可用 | fail-open | 论证：256-bit 密钥使在线爆破无意义，限流只是纵深一层；不为限流可用性牺牲接入可用性（该决策写入代码注释） |

### 6.6 命令面安全（纵深）

- **白名单命令集**：仅 §5.4 表内 8 类命令；未知 type 一律 `error/UNKNOWN_COMMAND`。
- **参数强校验**：`job_id` 必须 UUID 形态；`lines ≤ 500`；字符串字段限长。
- **无任意 shell / 无文件系统通路 / 无 SQL 直通**：排障需要上下文时，用 `snapshot`/`job.log.tail` 的结构化数据替代。
- **媒体可见性**：若命令返回媒体相关信息，必须经 `mediascope.ReadCond`（可见性唯一真源）——调试通道**不是**可见性豁免通道。

## 7. 操作审计日志（需求 6）

### 7.1 事件清单（全量落 audit 表，只增不删）

| action | 触发点 | detail 键（白名单） |
| --- | --- | --- |
| `debug.enable` | 开启成功 | `ttl_hours`, `expires_at`, `channel_fp` |
| `debug.disable` | 关闭（手动/到期 reaper 分开记） | `channel_fp`, `reason: manual\|expired` |
| `debug.rotate` | 重置密钥 | `old_channel_fp`, `new_channel_fp` |
| `debug.agent_connect` | 握手通过 | `channel_fp`, `agent_version`, `peer_ip` |
| `debug.agent_disconnect` | 连接结束 | `channel_fp`, `duration_s`, `close_code` |
| `debug.cmd` | **每条调试命令** | `channel_fp`, `cmd`, `job_id?`, `ok`, `latency_ms` |
| `debug.auth_fail` | 握手 401 | `channel_fp`, `peer_ip`, `reason` |
| `debug.locked` | 失败锁定触发/解除 | `peer_ip`, `window_s` |

### 7.2 字段与留存

| 项 | 设计 |
| --- | --- |
| 记录字段 | 复用 audit 表结构：`actor, action, target_type, target_id, detail(JSONB), ip, user_agent, created_at` |
| actor 口径 | 管理动作=管理员 user_id；agent 动作=`recordAs("agent:"+channel_fp)`（公开端点显式传 actor 的既有模式） |
| 留存策略 | 与全站审计一致（只增不删，保留策略沿用既有巡检/备份——mediadata 备份红线覆盖） |
| 可追溯链 | `谁开启(enable) → 谁接入(connect: IP/版本) → 执行了哪些命令(cmd×N) → 何时断开/关闭`——一行通道指纹贯穿全链 |

### 7.3 detail 键名红线

审计 `RedactDetail` 对键名命中以下子串（大小写不敏感）**整键剔除**（`audit.go:344-353`）：`password/passwd/pwd/secret/credential/apikey/api_key/private_key/signature/hash/token/jwt/bearer/session/cookie/authorization/otp/totp/mfa`。

- 本设计统一用 `channel_fp`（通道指纹=channel_id 前 8 位，非密钥摘要——注意 `key_digest` 命中 `hash` 子串，**禁入 detail**）、`peer_ip`、`agent_version`、`cmd`、`job_id`、`ok`、`latency_ms`、`ttl_hours`、`expires_at`、`duration_s`、`close_code`。
- 密钥明文**永不进审计**（生成/重置响应体是唯一出口；摘要也不进审计表——审计表永久保留，能少记就少记）。

## 8. 开启/关闭状态管理（需求 7）

### 8.1 状态机

```
                 enable(签发新凭据)                agent 接入
   [关闭]  ───────────────────────────>  [开启·待连接] ──────────> [开启·已连接]
     ^  ^                                    |    ^                     |
     |  └──────── disable/到期/重置 ──────────┘    └──── agent 断开 ────┘
     |                                          （连接子态，不改变通道态）
     └──────────────── disable（幂等）──────────────────────────────
```

| 当前态 | 事件 | 动作 | 结果 |
| --- | --- | --- | --- |
| 关闭 | enable | 生成新 channel_id+key，UPSERT 行，审计 | 开启·待连接 |
| 开启（任意连接子态） | disable | 踢连接(4003)，`enabled=false`，审计 | 关闭 |
| 开启 | rotate | 新凭据，踢旧连接(4004)，审计 | 开启·待连接 |
| 开启 | 到期（reaper/握手/心跳复核） | 踢连接(4001)，`enabled=false`，审计 | 关闭 |
| 开启 | enable（重复开启） | **409 `DEBUG_ALREADY_ENABLED`**——防止误操作轮换掉正在使用的密钥 | 不变 |
| 关闭 | enable（含刚过期） | 同首行：全新凭据 UPSERT | 开启·待连接 |

### 8.2 并发操作处理

| 场景 | 机制 |
| --- | --- |
| 管理员连点开启/双击 | 前端按钮 in-flight 期间禁用；后端 `pg_advisory_xact_lock(742032)` 事务内串行化（Job000107 同款先例），第二请求等待锁后读到"已开启"→ 409 |
| enable/disable/rotate 与握手并发 | 同一 advisory lock 覆盖凭据变更；握手侧读状态用同一行（FOR UPDATE 或锁后读），杜绝"换钥瞬间旧钥仍握手成功"窗口 |
| 双标签页同时操作 | 后端串行化兜底，结果一致（后到的拿到 409/204 如实响应） |
| WS 连接槽竞争 | 进程内 `atomic` 单槽 + upgrade 前检查（§5.2 步骤 3） |

### 8.3 一致性保障

- **库为唯一真源**：`debug_channel` 单行表；连接槽是进程内易失态（重启即清，agent 重连重建）。
- **单 api 副本前提**：连接槽/订阅表在 api 进程内，v1 部署=单 api 容器（compose 现状）成立；未来多副本需引入 Valkey 分布式连接锁——**该前提写入契约文档**，多副本化时为本功能列改造项。
- **前端一致性**：status 轮询 5s（开启态）；一切变更操作后即时 refresh 而非等轮询；倒计时由 `expires_at` 本地推算+轮询校准，不信赖前端时钟做权威判断。

## 9. 异常场景处理（需求 8）

| 场景 | 检测 | 处理 |
| --- | --- | --- |
| 连接中断（网络抖动/进程杀） | WS 读错/1006 | agent 指数退避重连（1s→2s→…→30s 封顶，±20% 抖动防惊群）；重连成功后服务端重发 snapshot 全量（事件流**不补发**，靠快照对齐） |
| 密钥连接中失效（rotate/disable/到期） | 管理动作触发踢连接 | Close 4004/4003/4001；agent 收到后**停止重连**并提示"密钥已失效，请联系管理员重新开启"（不重试 401/4004 类终态码） |
| 重复开启 | 后端 409 | 前端如实弹出"调试已开启"并刷新状态；不会轮换密钥 |
| 第二 agent 抢连 | upgrade 前 409 | 前端/agent 提示"已有活动调试连接"；如需换人，管理员 rotate 或先关闭 |
| 服务重启 | 进程退出 | 通道状态在库保留；agent 退避重连，有效期内自动恢复（连接子态重新建立，审计补 connect/disconnect 对） |
| 时钟跳变 | `expires_at` 用 DB `now()` 写入+复核 | 以 DB 时钟为权威；agent 本地倒计时仅展示用 |
| Valkey 宕 | 限流/失败计数失败 | fail-open（§6.5 已论证）；命令面不依赖 Valkey（订阅推送走进程内） |
| 管理员浏览器标签关闭 | — | 不影响通道（通道生命周期与管理员会话无关）；到期 reaper 兜底 |
| agent 长时间静默 | WS ping 30s 无 pong×2 | 服务端判定死连接，踢除（Close 1001）并记 disconnect；连接槽释放 |
| 消息超大/畸形 | 单帧上限 1MB（库默认）+ JSON 解析失败 | 关闭连接（Close 1007/1003），记审计 |
| 迁移回滚（down） | 部署流程 | debug_channel 表 DROP；api 重启后 /admin/debug/* 随代码回退消失，行为与"功能不存在"逐字节一致 |

## 10. 数据模型与 API 契约

### 10.1 DDL（新迁移 `00038_debug_channel.sql`）

```sql
CREATE TABLE debug_channel (
    id               BOOLEAN PRIMARY KEY DEFAULT true CHECK (id),  -- 单行表惯用法
    enabled          BOOLEAN NOT NULL DEFAULT false,
    channel_id       TEXT NOT NULL UNIQUE,
    key_digest       TEXT NOT NULL UNIQUE,        -- sha256(access_key) hex；明文永不入库
    created_by       UUID NOT NULL REFERENCES users(id),
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at       TIMESTAMPTZ NOT NULL,
    last_connect_at  TIMESTAMPTZ,
    last_connect_ip  TEXT
);
COMMENT ON TABLE debug_channel IS '远程调试通道（全局单行）；凭证明文仅在 enable/rotate 响应中出现一次';
```

down = DROP TABLE。迁移编号接当前 goose 37 之后（若 Job000120 被丢弃则顺延，实施期以当时 goose 版本为准）。

### 10.2 REST 端点（全部 `RequirePerm("admin:system")`）
