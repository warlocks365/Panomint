## 一、更新摘要

v1.6.0 解决「管理员关闭自动转码后，新导入的 360° 视频完全无法播放」的问题：此前播放链路强依赖 HLS 转码产物，闸门关闭（省算力的正当配置）会让未转码视频落入死局。本版本为播放链路补上**原始文件回退**分支——转码不再是可看的前提，而是清晰度增强。

### 1.1 新增与改动

| 模块 | 内容 |
| --- | --- |
| 360° 视频回退播放 | 无 HLS 产物时以原始文件直接播放：拖动环视、陀螺仪、VR 头显双眼模式全部保留；转码完成后自动切换为多档自适应流 |
| 播放页回退提示条 | 四态提示（转码中 / 转码失败保持原始 / 未转码+立即转码按钮 / 系统闸门关闭说明），替代原先的报错与空白 |
| 闸门语义软化 | 系统级「自动 HLS 转码」关闭时不再对 360° 视频报 409，而是回退原始播放；闸门 AND 语义逐字节未动（关闭时仅不自动发起，不放宽闸门测试） |
| 内存防护 | HLS 就绪切换后立即释放原始文件 blob 引用，避免 4K 视频双份内存驻留 |
| 清晰度切换 | 回退播放期间档位选择器自动隐藏（无多档可选），切回 HLS 后恢复 |

### 1.2 修复

| 问题 | 说明 |
| --- | --- |
| 播放页模板条件分支误配对 | 回退提示条插入后，普通视频分支的 `v-else` 与其错误配对，导致照片/全景照片/HLS 就绪态意外渲染空视频播放器；改为显式 `v-else-if` 结构性修复，e2e 增配对守卫与三态渲染回归（截图目检逮出） |

### 1.3 兼容性与质量

- **纯前端行为变更**：零 API 契约变更、零数据库迁移（API 契约 v1.16 仅记录前端行为）；既有部署升级后无需任何数据操作
- e2e 回归 37/37 ALL GREEN（含闸门守卫/配对守卫/三态渲染），最终产物三方指纹核验（本机 = 镜像 = HTTP 服出一致）
- 回归覆盖原则升级：e2e 同时断言「该在的在场」与「不该在的缺席」


## 三、升级注意事项

1. **从 1.5.x 升级**：拉取 `:1.6.0`（或 `:latest`）镜像重建 web 与 app 容器即可；无迁移、无配置变更。api + 常驻 worker（embed/tag/faces/phash）共用 app 镜像，需一并 recreate；index/transcode worker 镜像独立，本版未变更可不重建。
2. **360° 旧视频**：历史上因闸门关闭而无法播放的 360° 视频升级后立即可看（原始回退）；如需多档清晰度，播放页点「立即转码」或开启系统级自动转码。
3. **降级回滚**：回滚到 1.5.0 仅需把 image tag 换回 `1.5.0` 重建；无数据结构差异。
