### 6.2 本轮新踩的坑（DB 查询层面）

| 现象 | 根因 | 正确写法 |
|------|------|---------|
| `FATAL: database "pano" does not exist` | 库名是 `pano_album` | `-d pano_album` |
| `column "version" does not exist` | goose 表列名 `version_id` | `SELECT version_id FROM goose_db_version` |
| `column "gps_lat" does not exist` | GPS 是 PostGIS `geometry` 单列 `gps` | `WHERE gps IS NOT NULL` |
| `column "thumb_path"/"hls_path" does not exist` | 实际列名 `thumbnail_sm/md/lg`、`hls_master` | 见 §4.1 |
| `invalid input value for enum media_type: "null"` | `type` 是 enum，不能 `COALESCE(type,'null')` 再拼接 | 先 `type::text` |
| `aggregate functions are not allowed in GROUP BY` | 拼接串里含 `count(*)` 又按该表达式分组 | 用子查询：`SELECT ...||cnt FROM (SELECT ..., count(*) AS cnt ... GROUP BY ...) t` |
| `ORDER BY position 2 is not in select list` | 同上，派生列排序 | 子查询内 `ORDER BY cnt` |
| ⚠️ `\d media` 无法经 `docker exec -t` 正常取 | pty 问题 | 用 `docker exec -i` |

### 6.3 历史坑位（仍需警惕）

- **pg_trgm 相似度阈值**：`%` 运算符受 `pg_trgm.similarity_threshold`（默认 0.3）影响，`similarity('2024-03-03_photo_062.jpg','photo')=0.286 < 0.3` → 105 行全含 photo 却搜出 0。已全面改用 `ILIKE '%'||$n||'%'`（保留 GIN 索引加速）。
- **Nominatim 被 GFW 阻断**（容器内超时）→ resolver 错误已改为 `log.Warn` 不降级继续（消除 HTTP 500）；高德源按契约待密钥。
- **前端硬编码 localhost**（见 §5.2）。
- **详情 tags 缺 kind/color**：前端无法区分 user/ai 着色，已补 `DetailTagRef`。
- **agent 易漏传前端 dist**：部署后必须验证隧道线上 js 哈希与本地 `dist` 一致。
- **VMware 在线扩盘**后须 `echo 1 > /sys/block/sda/device/rescan`；parted 交互用 `printf 'Yes\n' | parted ---pretend-input-tty`。
- `/` 分区无法在线再扩（空间不相邻），分区表备份在服务器 `/root/part-backup/`。
