# GPU 远程链路实测报告 —— 方法是否有用？

- 日期：2026-09-03 01:25（会话跨日）
- 目的：不凭"应该有用"，用机械证据实测 `gpu.py python xxx.py` 这条远程 GPU 链路在真实工作负载下是否成立
- 场景：**Stage 4 AI embedding**（批量图像特征提取），5M 参数 CNN（ResNet-18 同级量级）

## 一、结论（一句话）

**方法确实有用**：端到端一条命令、自动化闭环、20.2 倍加速、结果与 CPU 一致到 1.7e-6；且 A 机本地根本没有 torch，这类任务**只能**靠远程 GPU 跑（或向本地环境装 CPU torch，本方案无需污染本地）。

## 二、测试环境

| 端 | 环境 |
|---|---|
| A 机（调用方） | 无 GPU、**无 torch**（仅 numpy 2.5.1、8 核）——任务本地无法执行 |
| B 机（192.168.1.41） | RTX 3090 24GB、32 核 CPU、torch 2.12.1+cu130 / CUDA 13.0 |
| 链路 | `gpu.py python bench_gpu_link.py`（与本地写法一致，自动：同步→别名替换→GPU 空闲探测→执行→runs/ 产物回传） |

## 三、实测数据（B 机同进程对比，权重与输入同源）

| 指标 | B机 CPU（32核） | RTX 3090 |
|---|---|---|
| 单张耗时 | 12.42 ms/张 | 0.62 ms/张 |
| 吞吐 | 80.5 张/s | **1,622.9 张/s** |
| **加速比** | — | **20.2×** |
| 峰值显存 | — | 1,711 MB（12 GB 配额内） |

**一致性校验**：同一模型权重、同一批输入，CPU 与 CUDA 输出的 512 维 embedding 最大绝对差 **1.68e-06**（atol=1e-3 判定一致）→ GPU 结果可信。

**真实入库规模外推**（按实测吞吐）：

| 入库量 | B机 CPU | RTX 3090 | 节省 |
|---|---|---|---|
| 1,000 张 | 12.4 s | 0.62 s | 11.8 s |
| 10,000 张 | 124 s (2.1 min) | 6.2 s | ~2 min |
| 100,000 张 | 1,242 s (**20.7 min**) | **62 s (1 min)** | 19.7 min |

## 四、方法的价值边界（诚实版）

**值得走远程 GPU**：批量 embedding / 向量化 / 训练 / 重推理——任务越重、单次调用聚合的批次越大，越值。

**不划算**：
- 单次固定开销约 **2~4 s**（同步 + GPU 空闲探测 + 排队检查 + 产物回传）。跑单张小图或轻量计算，开销占比过高。
- CPU 本就能秒级的活（如之前实测 8 段 720p 短视频软编共 13 秒）没必要上 GPU，本地跑即可。

**使用建议**：把批量任务**聚合成一次调用**（脚本内循环 batch），别一条命令处理一张图——否则每次都被 2~4s 开销稀释。

## 五、过程中踩到的两个测试脚本 bug（非链路问题）

1. 一致性校验把 `x.cpu()` 喂给了权重仍在 CUDA 的模型 → `Input type and weight type should be the same`。修法：统一输入源 + 单一模型实例先 CPU 后 `.cuda()`，保证权重天然一致。
2. 第一版模型太浅（0.5 ms/张），32 核 CPU 都轻松跑，测不出差距 → 加深到 5M 参数后差距拉到 20×。
   > 教训：**基准负载必须先让 CPU 侧明显吃力，才有区分度**。
