### 1.2 双份白名单问题（本次必须处理，F2）

现状是 **handler 硬编码 `if` + store map 两份**。只改 map 不改 handler，`granularity=day` 会被 handler 在触库前拦掉并返 400——**day 功能上线即失效，且测试可能全绿**（因为 store 层测试直接调 map）。这是典型的「沉默逻辑错误」。

**两种收敛方案**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **推荐**：handler 删掉硬编码 `if`，改查 map | handler 校验与 store 校验同源，`ErrInvalidGranularity` 从 store 返回后走 geo 同款的 `err == ErrInvalidGranularity` 分流 | 消除双份真源，与 geo 侧形态对齐；代价是 handler 从「不触库即拒」变为「先读 map 再拒」，**仍然不触库**（map 是内存查表），`TestDateHistogramGranularity` 里 `&Handler{}`（Store 为 nil）依然安全 |
| 保守：handler 的 `if` 补上 `\|\| granularity != "day"` | 改一行 | 保留双份真源，下次加档位仍会漏改一处 |

**采用推荐方案**。落地形态（对齐 `geo/handlers.go:249-257` 的可区分语义分流）：

```go
func (h *Handler) DateHistogram(c *gin.Context) {
	granularity := c.DefaultQuery("granularity", "month")
	scope, err := ResolveMediaScope(c.Query("space"), c.GetString("user_id"))
	if err != nil {
		rejectScope(c, err)
		return
	}
	buckets, err := h.Store.DateHistogram(c.Request.Context(), scope, granularity)
	if err != nil {
		// 可区分语义必须保留：粒度非法是本端文案（400），DB 故障固定文案（500）
		if errors.Is(err, ErrInvalidGranularity) {
			httperr.Envelope(c, http.StatusBadRequest, "INVALID_PARAMS", err.Error())
			return
		}
		httperr.Fail(c, http.StatusInternalServerError, "QUERY_FAILED", "查询失败", err)
		return
	}
	c.JSON(http.StatusOK, buckets)
}
```

注意：**守卫影响（必须知道）**：`ErrInvalidGranularity.Error()` 这一行**会被 `errtext_guard_test.go` 扫成命中**（`responseWritePatterns` 含 `httperr.Envelope(`，且行内含 `err.Error()`）。按 `errEchoRegistry` 的既有形态，必须新增一条登记项：

```go
{"internal/media/handlers.go", "DateHistogram", "if errors.Is(err, ErrInvalidGranularity) {",
 "httperr.Envelope(c, http.StatusBadRequest, \"INVALID_PARAMS\", err.Error())", false,
 "本端哨兵 ErrInvalidGranularity 的固定中文文案（「granularity 仅支持 year|month|day」）；同函数的 DB 故障分支走 httperr.Fail 固定文案"},
```

`MustFix=false`（本端自造文案，非 DB 原文），与 `errtext_guard_test.go:94` 的 geo 登记项**同形**。

**替代方案（守卫零改动）**：保留 handler 前置校验，但把判定改为查 map：

```go
if _, ok := histogramTrunc[granularity]; !ok {
	httperr.Envelope(c, http.StatusBadRequest, "INVALID_PARAMS", ErrInvalidGranularity.Error())
	return
}
```

此写法**行内容与现状完全一致** ⇒ `errtext_guard_test.go` 侧**零改动**，且双份真源也收敛为一份（map）。**这是更优解：同时拿到「消除双份真源」和「守卫零改动」，推荐采用此方案。**

### 1.3 SQL 实现与索引评估

**SQL 骨架逐字节不动**（`histogram.go:38-41`）：

```sql
SELECT COALESCE(to_char(date_trunc('%s', m.taken_at), '%s'), 'unknown') AS bucket, count(*)::int
FROM media m WHERE <scopeConds + deleted_at IS NULL>
GROUP BY 1 ORDER BY 1 ASC
```

`granularity` 只影响两个**受控字面量**的注入（`g.trunc` / `g.fmt`），二者来自包内 map，**不接受外部输入**——不存在 SQL 注入面。`%s` 拼接在 map 白名单下是安全的，这与现状同构。

**索引评估**：

| 项 | 结论 |
|---|---|
| 现存索引 | `idx_media_taken ON media(taken_at DESC)`（F6） |
| `date_trunc('day', taken_at)` 能否走索引 | **不能**。`date_trunc` 是表达式，裸 `taken_at` 索引无法用于 `GROUP BY date_trunc(...)` 的分组有序性 |
| 是否需要新索引 | **不需要**。理由：① 本查询是**聚合扫描**（无 `WHERE` 收窄时间范围），本来就必然扫全量 `media` 行，加索引只能省排序、不能省扫描；② 桶基数上界 = 天数（10 年 ≈ 3650），`HashAggregate` 的分组数完全可控；③ geo 侧 `day` 与 `/media?view=day` **已在生产跑同一形态**（F4/F5），无先例问题 |
| 若将来加 | 表达式索引 `CREATE INDEX ON media (date_trunc('day', taken_at))`，但需**先实测 `EXPLAIN`** 证明聚合扫描是瓶颈。**本次不做**（无迁移 = 无回滚风险） |
| 迁移文件 | **不新增**。`migrations/` 停在 `00047`，本次不产生 `00048` |

## 2. 前端增量设计

### 2.1 维度参数化：把 `MONTH_H`/`DAY_H` 改为按档位查表

**问题定位（F7）**：高度常量在 JS（`useTimelineGrouping.js:7-8`）与 CSS（`TimelineGrid.vue:283-296`）**各写一份**，靠人工同步。泛化后档位×level 变二维，硬编码 `switch` 会退化成多份重复分支。

**方案：单一高度表 + CSS 变量下发**。

新建 `src/frontend/src/components/timeline/timelineDimensions.js`（纯数据 + 纯函数，无 Vue 依赖，可单测）：

```
/** 档位 → 该档位唯一可见标题的高度（px）。唯一真源，CSS 通过 :style 变量消费同一值。 */
export const HEADER_HEIGHT = { year: 56, month: 46, day: 34 }
```

**语义（已按团队裁决修正）**：档位即**唯一可见的标题粒度**，不是「最细可见粒度」。

| 档位 | 唯一产出的标题 | 高度 | 字号 | 字重 |
|---|---|---|---|---|
| `year` | `2024年` | **56px**（新值） | `--font-size-lg` 16px | 600 |
| `month` | `2024年6月` | **46px**（沿用现状） | `--font-size-lg` 16px | 600 |
| `day` | `2024年6月14日` | **34px**（沿用现状） | `--font-size-sm` 13px | 500 |

- **year 档不产出 month/day 标题；month 档不产出 day 标题；day 档只产出 day 标题**（PM 验收标准 A1/A2/A3，A1 为 P0）。
- **高度必须差异化**：视觉层级「年 > 月 > 日」。取 `56 > 46 > 34`：月/日沿用现状值（46/34）保证既有观感零变化，年档取 56 拉开层级。字号受令牌上限约束——`tokens.css` 最大为 `--font-size-lg: 16px`（`:49`），故年档靠**高度 + 字重**而非更大字号拉开层级，**不新增颜色值、不硬编码 px 字号**。
- 与现状差异：现状是「月+日两级标题恒定渲染」，本次改为**按档位单级渲染**。`month` 档与现状观感一致（仅去掉日标题），`day` 档与现状日标题一致（仅去掉月标题），`year` 档为全新视图。

配套导出：

```
export const DIMENSIONS = ['year', 'month', 'day']            // 档位枚举（白名单）
export function headerKeyOf(dimension, date)   // 'YYYY' | 'YYYY-MM' | 'YYYY-MM-DD'
export function headerLabelOf(dimension, date) // '2024年' | '2024年6月' | '2024年6月14日'
export function headerHeightOf(dimension)      // 56 | 46 | 34
export function bucketPatternOf(dimension)     // /^\d{4}$/ | /^\d{4}-\d{2}$/ | /^\d{4}-\d{2}-\d{2}$/
export function anchorKeyOf(dimension, date)   // 该档位下用于锚点定位的键
```

**与 `DynamicScroller :min-item-size` 的关系（关键约束）**：

现状 `TimelineGrid.vue:15` 写死 `:min-item-size="34"`，取的是**最小标题高度**（`DAY_H`）。

- vue-virtual-scroller 的 `min-item-size` 是所有流元素的**尺寸下界估计**；若实际元素比它小，滚动条总高算小、出现滚动抖动。
- **故不变式为：`min-item-size` 必须 ≤ 三档中最小标题高度**。最小值仍是 `day` 档的 **34px**，与现状一致 ⇒ **`:min-item-size="34"` 无需改动**。
- 若后续把 `HEADER_HEIGHT.day` 调到 34 以下，**必须同步下调 `min-item-size`**，否则年/月档一旦切到 day 档即出现滚动抖动。此约束须写入代码注释（属「已知坑」，见知识库 spec-as-contract 要求）。

**日期键解析统一走此模块**，`useTimelineGrouping.js` / `useTimelineSeek.js` / `DateSlider.vue` **共用**，杜绝三处各写一份 `pad2`/正则导致的漂移（现状 `pad2` 从 `useTimelineGrouping.js:17` 导出给 `useTimelineSeek.js:2` 复用，是好范式，沿用）。

### 2.2 `monthIndex` → `headerIndex`（泛化，保留而非另加）

**决策：泛化为 `headerIndex`，不保留 `monthIndex`、也不新增 `yearIndex`/`dayIndex`。**

理由：
- 若三张 map 并存，则**同一份 `flat` 要维护三份索引**，且调用方要按档位选 map——把「当前档位」这个状态泄漏到每个消费点。
- 泛化为单张 `Map<anchorKey, index>` 后，**键的形态由档位决定**（`2024` / `2024-06` / `2024-06-14`），调用方只传「该档位的锚点键」，无需知道内部细节。
- `monthIndex` 的唯一消费点是 `useTimelineSeek`（F8），而 `useTimelineSeek` 本次必然要改，**保留旧名等于留一个无人使用的兼容层**。

```
// 语义：当前档位下「唯一可见的分组标题」键 → flat 索引
// 注意：档位即唯一可见粒度，故 flat 中只可能有一种 level 的 header，
// 无需再按 level 过滤（原先的 isHeaderVisible 已随语义修正删除）。
const headerIndex = computed(() => {
  const map = new Map()
  flat.value.forEach((it, i) => {
    if (it.header && it.anchorKey) map.set(it.anchorKey, i)
  })
  return map
})
```

**键空间随档位收窄**（三档键形态互不相同，故 `headerIndex` 在同一档位内无歧义）：

| 档位 | `anchorKey` 形态 | 示例 |
|---|---|---|
| `year` | `YYYY` | `2024` |
| `month` | `YYYY-MM` | `2024-06` |
| `day` | `YYYY-MM-DD` | `2024-06-14` |

每个 header 元素新增字段 `anchorKey`（该档位下的键），并保留 `monthKey`（`day`/`month` 档的标题仍需它做键前缀，且与现状兼容）。`level` 字段保留但语义收窄为「= 当前档位」，CSS 仍按 `:class="item.level"` 取样式。

三档键均为**定长 + 零填充**，故字典序与时间序一致——这是 §2.4 锚点兜底可用字符串直接比较的前提，不可为了「缩短键」破坏零填充。

### 2.3 `DateSlider.vue` seek 载荷泛化

**现状（F9）**：正则 `/^\d{4}-\d{2}$/` 硬过滤、`monthKeyAt()` 只吐 `YYYY-MM`、桶时间轴用 `new Date(y, m, 1)` / `new Date(y, m-1, 1)`。

**泛化为按档位的桶适配器**（仍在 `timelineDimensions.js` 内，纯函数）：

| 档位 | 桶键正则 | 桶代表时间 | 范围下界 | 范围上界 |
|---|---|---|---|---|
| `year` | `/^\d{4}$/` | 当年 7/1 | 最旧年 1/1 | 最新年 **+1** 年 1/1 |
| `month` | `/^\d{4}-\d{2}$/` | 当月 15 日 | 最旧月 1 日 | 最新月**次月** 1 日 |
| `day` | `/^\d{4}-\d{2}-\d{2}$/` | 当日 12:00 | 最旧日 00:00 | 最新日**次日** 00:00 |

seek 载荷：`{ dimension, key }` **对象**，而非裸字符串。理由：裸字符串无法自证档位，`useTimelineSeek` 收到 `'2024-06'` 时无法区分它来自 month 档的合法请求还是 day 档的误请求——这正是「沉默逻辑错误」的高发区。对象载荷让不匹配**显式失败**（见 §2.4）。

`dragLabel` 同步走 `headerLabelOf(dimension, date)`，年档显示 `2024年`、月档 `2024年6月`、日档 `2024年6月14日`，与分组标题**逐字同源**。

注意：**`DateSlider.vue` 当前 192 行**，加维度分支会超 300 行红线（`MAX_LINES=300`，非棘轮登记项 ⇒ **任何新增即 FAIL**）。故桶适配与范围计算**必须外移到 `timelineDimensions.js`**，`DateSlider.vue` 只留「按 dimension 取适配器 → 渲染刻度/handle/bubble」。目标：**改动后仍 < 300 行**。

### 2.4 锚点跳转精确定位算法

**现状问题（F8）**：`monthIndex.get(key)` 未命中时线性扫「第一个 `monthKey <= target` 的月分组」。在 month 档下正确；但泛化后有两个隐患：
1. 扫描条件写死 `it.level === 'month'`，换档位即失效；
2. **落点是「第一个不晚于目标的分组」**，若目标月份无媒体会落到**上一个**有媒体的分组——这本身是合理兜底，但**必须显式承认**，否则用户以为跳到了目标月。

**新算法（三段式，档位无关）**：

```
seekTo({ dimension, key }, scrollEl):
  1) 前置守卫：dimension !== 当前档位 → 直接 return（不匹配显式失败，不猜）
  2) 翻页：while (!finished && guard < 300) { last = 最后已加载媒体的 anchorKey;
                if (last === 'unknown' || last <= key) break; await loadMore() }
     注意：last <= key 的比较对 YYYY / YYYY-MM / YYYY-MM-DD 三种键**均成立**
        （定长 + 字典序与时间序一致），无需按档位分支
  3) 定位：idx = headerIndex.get(key)
            ?? 兜底 = 最后一个 anchorKey <= key 的 header
            ?? 再兜底 = 0（目标早于所有媒体 → 回到顶部）
     scrollEl.scrollTo({ top: offsets[idx], behavior: 'smooth' })
```

**「不落到分组标题中间的错误位置」如何被保证**：

- `offsets[idx]` 是**该 header 元素自身的顶部 y**（`useTimelineGrouping.js:76-85` 逐元素累加，header 元素占自己的整段高度）。因此落点必然是标题行的**上沿**，其后紧跟第一条媒体行——**永远不会停在标题的垂直中段**。
- 兜底取「**最后一个** `<= key`」而非「第一个」：现有 month 实现在流按时间**倒序**（新→旧）的前提下取第一个满足 `<=` 的 header，等价于「最新的、不晚于目标的分组」；泛化后改为**显式取最大 key 的那个**，语义与档位无关、不依赖遍历顺序假设。
- 若 `key` 精确命中但该分组 `offsets[idx]` 因虚拟滚动尚未测量而偏小：`DynamicScrollerItem` 用 `:size-dependencies="[cols]"` 重算，**header 高度是定值常量**（不依赖 cols），故 offsets 不受 cols 变化影响——这是现有设计的有利条件，**参数化时必须保持「header 高度与 cols 无关」**，否则 offsets 与实际渲染高度会漂移。

### 3.3 完整请求/响应定义与错误码

**请求**：`GET /media/date-histogram?granularity={year|month|day}&space={personal|shared}`
- 注意：**路径无 `/api/v1` 前缀**（F1）。写成 `/api/v1/media/date-histogram` 会落到 SPA 回退、返回**假 200 的 HTML**，是本项目最易踩的坑。
- 认证：Bearer JWT（`authed` 组 + `permRead` 权限，`main.go:226`）。

**成功响应 `200`**（`c.JSON(http.StatusOK, buckets)`，**裸数组**，非 `{buckets:[...]}` 包裹）：

```json
[
  { "bucket": "2024",       "count": 1820 },
  { "bucket": "2024-06",    "count": 143 },
  { "bucket": "2024-06-14", "count": 12 },
  { "bucket": "unknown",    "count": 3 }
]
```

| 字段 | 类型 | 约束 |
|---|---|---|
| `bucket` | string | `^\d{4}$` / `^\d{4}-\d{2}$` / `^\d{4}-\d{2}-\d{2}$`，或字面量 `unknown` |
| `count` | int | `count(*)::int`，非负 |

**错误响应**（`httperr` 统一封套 `{ "error": { "code", "message" } }`）：

| 状态码 | `error.code` | `message` | 触发条件 |
|---|---|---|---|
| `400` | `INVALID_PARAMS` | `granularity 仅支持 year|month\|day` | `granularity` 非三档之一 |
| `400` | `INVALID_PARAMS` | `space 仅支持 personal\|shared` | `space` 枚举外（**触库前**拒绝，不回显 PG 枚举原文） |
| `401` | `UNAUTHENTICATED` | 身份缺失文案 | 无 `user_id` |
| `500` | `QUERY_FAILED` | `查询失败`（固定文案，完整错误只进服务端日志） | DB 故障 |

**可区分语义不变量**：粒度非法必须是 `400/INVALID_PARAMS` + 本端文案，**不得**被统一成 `500/查询失败`——那会把用户参数写错伪装成服务故障。`geo/handlers.go:249-251` 的注释已把这条列为本仓共识，media 侧改造后必须保持。
