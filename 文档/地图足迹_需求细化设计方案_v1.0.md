## 0 摘要（结论前置）

### 0.1 需求一句话

在地图页新增「足迹」开关：开启后，按**当前地图缩放比例**与**当前选定时间范围**，自动把各停留地点按时间顺序连成**带动效的弧形足迹线**（左往右下弧、右往左上弧），并**自动去除重叠线**。

### 0.2 三条关键结论

| 编号 | 结论 | 依据 |
|---|---|---|
| C-1 | **必须新增一个后端端点**（`GET /geo/footprint`） | 现有四个地图数据端点都无法提供「按时间排序的完整点序」：`/geo/clusters` 只返回聚合质心与计数（时间序丢失）；`/geo/items` 是 bbox 散点且 `limit` 默认 200 / 上限 1000，截断发生在排序之后，拿不到完整序列；`/geo/histogram` 无坐标；`/geo/places` 无坐标无时间序 |
| C-2 | **弧线方向与去重可精确形式化，且全部是纯前端视觉规则** | 后端只负责输出「有序停留点 + 去重后的段」，弧线几何、方向、动效由前端生成。好处：缩放/投影变化时无需回源，且规则可在本地即时调参 |
| C-3 | **缩放分级有现成地基，零新建** | 后端 `geo.GridSize(zoom)`（z0 = 180°，逐级减半）已在 `/geo/clusters` 用于网格聚合；前端 `reload()` 已把 `map.getZoom()` 传给后端。足迹的网格吸附与簇聚合完全同源，仅多一步「按时间连续合并」 |

### 0.3 一句话解释「为什么不能用现成端点凑」

簇是「一堆点的重心」，用它连线等于把「地理位置分布」当成「行动顺序」——同一个城市上午和下午的照片被压成一个点，时间序彻底消失；而条目端点有硬上限，超限时是「截断后再返回」，连不完整更谈不上顺序。所以足迹必须有自己的一条查询路径。

### 0.4 与现有功能的边界

| 项 | 说明 |
|---|---|
| 是否改动现有簇 / 筛选 / 时间轴行为 | **不改**。足迹是叠加层，开关关闭时零副作用 |
| 是否需要新的第三方依赖 | **不需要**。弧线用贝塞尔采样生成 GeoJSON，地图引擎与动效库（MapLibre GL、GSAP）均已在用 |
| 是否影响分享页 / 移动端 | 地图页本身在移动端可用；足迹开关随顶栏自适应（移动端仅显图标） |

## 1 需求背景与目标

### 1.1 需求原文

> 「另外再规划一个地图模块的足迹功能，在地图页加一个按钮，打开足迹功能后地图上按照当前地图缩放比例自动生成按当前选定时间范围的各地点间的行动足迹线（有动效的弧形足迹线段，从左往右下弧线，从右往左上弧线，自动去除重叠线）。该功能进行需求细化设计方案后生成汇报文件和效果原型」

### 1.2 拆解为七个可验收要素

| 编号 | 要素 | 验收口径 |
|---|---|---|
| F-1 | 地图页新增按钮 | 顶栏可点，开/关两态，状态可持久化（重进页面保持） |
| F-2 | 按当前缩放比例生成 | 缩放变化 → 网格粒度变化 → 线的数量与跨度自动变化（250ms 防抖） |
| F-3 | 按当前选定时间范围生成 | 时间轴框选 / 清除 → 足迹随之重算；无时间轴时按「全部时间」 |
| F-4 | 各地点间的行动足迹线 | 相邻停留点按时间顺序连线，端点落在停留点质心 |
| F-5 | 有动效的弧形足迹线段 | 入场生长动画 + 悬停反馈 + （可选）常驻流光；`prefers-reduced-motion` 下全部关闭 |
| F-6 | 从左往右下弧线，从右往左上弧线 | 见 §5.2 精确形式化（含退化与边界） |
| F-7 | 自动去除重叠线 | 见 §5.3 去重规范（两层：同向重复合并 + 近似重合合并） |

### 1.3 非目标（本期明确不做）

| 不做项 | 原因 |
|---|---|
| 真实连续 GPS 轨迹 | 相册只有拍摄点，属**稀疏采样**；不存在连续轨迹数据 |
| 速度 / 交通方式推断 | 稀疏采样无法可靠推断（两个城市间一张照片可能相隔数天） |
| 轨迹回放（时间滑块驱动） | 与现有时间轴语义冲突，另立需求再议 |
| 后端持久化「足迹」实体 | 足迹是**视图**不是数据；每次按条件实时计算，避免引入不一致 |
| 批量编辑 / 足迹导出 GPX | 本期不做，可在二期后段评估 |

### 2.2 后端 geo 能力（现状）

| 端点 | 用途 | 关键限制（本次侦察确认） |
|---|---|---|
| `GET /geo/clusters` | bbox + zoom 网格聚合 | 只返质心 + 计数 + 代表图，**无时间序**；`ORDER BY count DESC` |
| `GET /geo/items` | bbox 内媒体条目 | `limit` 默认 200、上限 1000；**先 `ORDER BY taken_at DESC` 再截断** → 只能拿到"最近的 N 条" |
| `GET /geo/histogram` | 时间分布直方图 | 无坐标 |
| `GET /geo/places` | 去重地名列表 | 无坐标、无时间序 |
| `GET /map/search` | 地名正向检索 | 与足迹无关 |

### 2.3 数据基础

| 项 | 现状 |
|---|---|
| 坐标列 | `media.gps`，类型 `geometry(Point,4326)`；GIST 索引 `idx_media_gps` |
| 时间列 | `media.taken_at timestamptz`，**可空** |
| 媒体类型 | 照片 / 视频 / 全景照片 / 全景视频**共用同一坐标列**，无类型差异（无 GPS 时该列为 NULL） |
| 可见性 | 唯一真源 `internal/mediascope`，接口 `VisibleCondFor(start, userID, alias)`；`userID` 为空时谓词收敛为恒假（FailClosed） |
| 坐标系 | 请求 bbox 一律 WGS-84；响应坐标按 `provider=amap` 转 GCJ-02（与高德栅格底图对齐） |

### 2.4 三条硬约束（实装前必须处理）

| 编号 | 约束 | 处理 |
|---|---|---|
| H-1 | `internal/geo/media_store_visible_test.go` 存在「源码中 `FROM media` 恰好 5 处」的**形状守卫测试** | 新增第 6 处查询时同步把断言从 5 改为 6，并补充可见性用例 |
| H-2 | `baseCond` **不含 `taken_at IS NOT NULL`** | 足迹查询必须自行补该条件——无时间戳的点无法定序，混入会污染序列 |
| H-3 | 前端 `ui-prefs` 写入是**整行替换**语义 | 新增 `map_footprint_on` 键后，`useMapUiPrefs` 的全量键清单必须同步携带，否则会把其他模块偏好清回默认 |

### 2.5 已确认可复用的地基

| 地基 | 位置 | 复用方式 |
|---|---|---|
| 缩放 → 网格 | `geo.GridSize(zoom)` | 足迹停留点吸附用同一函数，保证与簇聚合粒度**视觉同源** |
| 缩放传参 | `useMapData.reload()` 已把 `map.getZoom()` 传后端 | 足迹请求沿用同款参数 |
| 时间范围 | `range = { from, to }`（UTC ISO 闭区间）、`granularity` | 足迹请求直接吃同一 `range` |
| 防抖与竞态 | `scheduleReload()` 250ms + `reloadSeq` 代次守卫 | 足迹沿用同一模式（独立 seq，避免与主数据互相干扰） |
| 地图事件 | `moveend` / `zoomend` → `hooks.onMoveEnd` | 足迹挂同一条接线 |
| 动效库 | 项目已用 GSAP（时间轴入场动画） | 足迹入场动效可复用 |

## 3 交互设计

### 3.1 按钮落位

位置：**地图页顶栏**（`MapTopbar.vue`），「图标」按钮左侧。

| 属性 | 规格 |
|---|---|
| 尺寸 | 与现有 `.mt-icon-btn` 一致（含图标 16×16 + 可选文字） |
| 图标 | 足迹 / 路线语义，取自项目既有图标库（`gen_icon_sheets.py` 产出，实施前核对名称） |
| 文案 | 桌面端显示「足迹」；移动端仅图标 |
| 测试钩子 | `data-testid="map-footprint-toggle"` |
| 默认态（关） | 描边 1px 中性色，透明底 |
| 激活态（开） | 描边转品牌琥珀 + 8% 琥珀底 + 文字转主文本色 |
| 禁用态 | 视野内无任何带 GPS 媒体时不置灰（保持可点，给出空态提示），避免"不知道为什么不能点" |
| 状态记忆 | 写入 ui-prefs 新键 `map_footprint_on`（默认 `false`） |

### 3.2 状态机

```
[关] ──点击──> [加载中] ──有数据──> [已显示]
   <──点击──┘         └──无数据──> [空态提示（浮层 2.5s 自动消失，保持开关为开）]

[已显示] ──视野/时间/筛选变化──> [重算（静默，不闪空态）]
```

要点：
- 重算时**不显示全局 loading 遮罩**，只在顶栏按钮内显示极小的旋转指示，避免地图"闪"；
- 空态判定为「停留点 < 2」，提示文案：「当前范围不足两个地点，无法连线」（比"无数据"更准确地说清了成因）；
- 关闭开关立即清空图层与 source（`removeLayer` / `removeSource`），不留残余。

### 3.3 与其他交互的协同矩阵

| 交互源 | 变化 | 足迹行为 |
|---|---|---|
| 地图平移 / 缩放 | `moveend` / `zoomend` | 250ms 防抖后重算（沿用现路径） |
| 时间轴拖拽框选 | `range` 变化 | 立即重算（走 `onRangeChange`，与主数据同拍） |
| 时间轴「清除」 | `range = null` | 重算（全部时间） |
| 时间轴粒度切换（年/月/日） | `granularity` 变化 | **不影响足迹本身**（足迹只吃 `range` 的 from/to，与直方图粒度无关） |
| 筛选栏类型切换 | `kind` 变化 | 重算（足迹只连对应类型的点） |
| 图标模式切换 | `applyMarkerMode` | 互不影响；足迹线始终为线，不参与图标/缩略图切换 |
| 搜索定位 | `flyTo` | 视图变化 → `moveend` 触发重算（自然联动） |
| 点击簇展开列表 | 展开条目面板 | 足迹保持显示；列表面板打开时不遮挡足迹线（层级：列表 < 足迹线？见 §7.4） |

### 3.4 显示层级策略

MapLibre 图层顺序（自下而上）：

```
底图栅格瓦片（高德反代）
行政区/注记（底图自带）
footprint-lines      ← 足迹线（本次新增）
footprint-ends       ← 端点标记（停留点小圆）
cluster-circles      ← 现有簇圆
cluster-thumbs       ← 现有缩略图
hover / tooltip 等 HTML 覆盖层（DOM，永远在最上）
```

理由：足迹线在簇**之下**，避免遮挡缩略图圆点；但高于底图注记，保证视觉可读。端点标记在簇之下、线之上，形成"线串珠"的层次。

### 3.5 图例（可选，待裁决）

地图右下角默认不显示图例。悬停线时通过卡片给出全部语义（起讫地、次数、时间窗），避免常驻图例占屏。若用户希望常驻说明，可在偏好中开启（本方案默认不做）。

## 4 核心算法规范（一）：从照片到停留点

### 4.1 数据链总览

```
media 点列（时间升序；仅当前可见 + 当前时间范围 + 当前筛选 + 当前视野）
        │
        │  ① 网格吸附：ST_SnapToGrid(gps, GridSize(zoom))
        ▼
网格单元序列（每个点带 cell 标识）
        │
        │  ② 连续同格合并（窗口函数：lag 标记边界 + 累加分组）
        ▼
停留点序列 stops[] （质心坐标 / 首次时间 / 末次时间 / 张数 / 地名 / 代表图）
        │
        │  ③ 相邻配对：(i, i+1) 生成有向段
        ▼
有向段序列（原始，含全部重复）
        │
        │  ④ 同向去重：同一有向对合并，trips = 出现次数
        ▼
最终段集（前端渲染）
```

### 4.2 「缩放分级」的实现（兑现 F-2）

复用后端 `geo.GridSize(zoom)`：`g = 180 / 2^zoom`，下限 `0.0005°`。

| 缩放 | 网格边长 | 尺度感 | 足迹表现 |
|---|---|---|---|
| 4 | 11.25° | 大洲 | 极少数跨区弧线 |
| 5 | 5.625° | 省 / 大区 | 跨省长弧 |
| 8 | 0.703° | 城市群 | 城际弧 |
| 10 | 0.176° | 城市 | 市内弧 |
| 12 | 0.0439° | 区县 | 区内弧 |
| 14 | 0.0110° | 街道 | 街区弧 |
| 16 及以上 | 0.0005°（下限） | 建筑 | 极细弧（受上限保护，见 §4.5） |

**这是「按当前地图缩放比例自动生成」的准确落点**：用户改变缩放 → 网格边长变化 → 停留点粒度变化 → 足迹线的数量与跨度自动改变。放大时一个城市会"炸开"成多个停留点，缩小时多个停留点又"收拢"成一团——这正是用户期望的探索体验。

### 4.3 停留点合并算法（关键差异点）

**必须用「按时间连续同格合并」，不能用「按空间聚类」。**

| 方案 | 行为 | 后果 |
|---|---|---|
| 空间聚类（如按格分组） | A→B→A 三次访问的 A 会被合成一个点 | 往返消失，序列退化为 [A, B]，**丢失"来回"语义** |
| **时间连续同格合并（推荐）** | 序列保留 [A, B, A] | 往返保留，可画出"一去一回"两条弧 |

实现要点：

| 要点 | 做法 |
|---|---|
| 边界标记 | `CASE WHEN cell IS DISTINCT FROM lag(cell) OVER (ORDER BY taken_at) THEN 1 ELSE 0 END` |
| 分组 | `sum(is_new) OVER (ORDER BY taken_at)` 作为组号 |
| 组内坐标 | `ST_Centroid(ST_Collect(gps))` —— 用质心而非"取第一张的坐标"，避免同格内多点被压到边缘 |
| 组内时间 | `min(taken_at)` / `max(taken_at)` |
| 地名 | 取组内**最近一次**非空 `place`（越新越准） |
| 代表图 | 取组内 `taken_at` 最新且有缩略图的媒体 id |

**排序稳定性**：`ORDER BY taken_at, id` —— 同一秒多张照片时用 id 兜底，避免不同查询间顺序抖动（抖动会直接改变连线拓扑）。

### 4.4 序列截断与保护

| 保护项 | 阈值 | 超限行为 |
|---|---|---|
| 原始点列 | 5000 | 截断（`truncated = true`），并按已取部分计算 |
| 停留点 | 200 | 截断 |
| 段 | 400 | 截断 |

**为什么需要**：低缩放大范围（如 zoom 4 看全国十年）时，原始点可能是数十万。截断必须发生在**排序后按时间等距采样**，而不是简单取前 N 条——否则会得到"只有最早几年"的足迹，视觉上欺骗用户。

**推荐采样策略**：若点列超过上限，按 `row_number() % step = 0` 等距抽取（step = ceil(总数 / 上限)），保证时间分布均匀，并在响应中置 `truncated = true`，前端提示「数据量较大，已按时间等距抽样」。

### 4.5 退化情形（算法层）

| 情形 | 处理 |
|---|---|
| 停留点 = 0 | 空态：「当前范围没有带位置的照片」 |
| 停留点 = 1 | 只显示端点标记，不显示线；提示「当前范围只有一个地点」 |
| 停留点 = 2 且两点同格 | 经过合并后应只剩 1 点（同格已合并） |
| 相邻两点坐标完全相同 | 跳过该段（零长度段无意义） |
| 媒体无 `taken_at` | 排除（无法定序） |
| 媒体无 `gps` | 排除（`baseCond` 已有该条件） |
| 跨 ±180° 经线 | 经度差取最短弧（wrap 到 [-180,180]）；本期目标区域（中国）不涉及，仅做防御 |
| 高纬度畸变 | §5.1 的米制校正自动补偿 |

## 5 核心算法规范（二）：弧线几何、方向、去重

### 5.1 弧线几何生成（前端纯函数）

对一条段的两个端点 `P1(lng1, lat1)`、`P2(lng2, lat2)`：

**步骤 1｜换算为等距平面坐标（米制校正）**

直接把经度差当平面用会产生偏差（1° 经度 ≈ 111 km × cos(纬度)，在中国约 0.75–0.85 倍）。做法：

```
latM = (lat1 + lat2) / 2
x1 = lng1 · cos(latM),  y1 = lat1
x2 = lng2 · cos(latM),  y2 = lat2
```

**步骤 2｜求中点与法线**

```
Mx = (x1 + x2) / 2,  My = (y1 + y2) / 2
dx = x2 - x1,        dy = y2 - y1
len = hypot(dx, dy)            // 若 len 为 0 → 跳过该段
nx = -dy / len,       ny = dx / len    // 单位法线
```

**步骤 3｜法线定向（受 §5.2 方向规则支配）**

```
s = sign2(dx)   // dx > 0 → +1；dx < 0 → -1；dx = 0 → 见 U-1
// 目标：dx > 0 时弧向南凸（下弧）；dx < 0 时弧向北凸（上弧）
// 法线 (nx, ny) 的 y 分量符号决定"向南/向北"
if (ny · s > 0) { nx = -nx; ny = -ny }   // 统一翻到 y 分量为负的一侧
```

> 实现时更稳的写法：直接把控制点 y 坐标设为 `My - |k · len|` 而 x 取中点附近，即 **控制点恒偏向纬度更小的一侧（南）当 `dx > 0`，偏向纬度更大的一侧（北）当 `dx < 0`**。这一写法对退化输入（dy 极大）更稳健。

**步骤 4｜控制点与采样**

```
k = 曲率系数（见 §5.4）
Cx = Mx + nx · k · len,   Cy = My + ny · k · len
t ∈ {0, 1/24, 2/24, …, 1}
B(t) = (1-t)²·P1 + 2(1-t)t·C + t²·P2      // 二次贝塞尔
```

采样 25 个点（24 段）后把 `x` 反算回经度（除以 `cos(latM)`），得到 GeoJSON `LineString`。

**为什么采样而不是直接用 3 个点**：地图引擎对 3 点折线是**直线插值**，视觉上是"两段折线"而非弧线；采样后视觉平滑，且与地图投影变形自然一致。

**为什么用地理坐标而非屏幕像素**：几何一旦写入 source 就固定在地理坐标上，地图缩放时引擎自行重投影。用屏幕像素算控制点只在生成时那个缩放级别视觉正确，用户一缩放就失真——除非在每次地图变换时重算全部几何（段数多时明显掉帧）。

### 5.2 弧线方向规则（F-6 精确形式化）

用户原话：「从左往右下弧线，从右往左上弧线」。

**形式化定义**：

> **规则 D**
> 设一条段的两个端点按时间顺序为 `From → To`，经度差 `Δlng = wrap(lngTo − lngFrom)`。
> - `Δlng > 0`（向**东**行进，画面上"从左往右"）→ 弧线**向南凸**（下弧）
> - `Δlng < 0`（向**西**行进，画面上"从右往左"）→ 弧线**向北凸**（上弧）

**关键推论（这解释了规则为何这样设计）**：

同一对地点的「去程 A→B」与「回程 B→A」其 `Δlng` 符号相反——
去程画下弧、回程画上弧，两条弧**镜像对称、上下分离**，天然构成一个「梭形 / 叶片」。

因此：两点之间最多出现两条弧（一去一回），往返关系一目了然，且两条弧互不遮挡。**这是本规则的核心价值，不是"随便定个方向"。**

**退化与边界**：

| 情形 | 处理（推荐） |
|---|---|
| `Δlng = 0`（正南北） | 按"从左往右"处理 → 下弧（保持规则单一，见 U-1） |
| `Δlng` 极小（近似南北） | 同上；实现上用 `sign2(dx)` 的零值分支处理，无需额外阈值 |
| 跨越 ±180° 经线 | `wrap(Δlng)` 取最短弧方向（防御性实现） |
| 南北跨度极大（如哈尔滨→三亚） | 米制校正后 ny 分量主导，弧度可能显得偏平；§5.4 的自适应曲率会补偿 |

### 5.3 去重规范（F-7 精确形式化）

由 §5.2 可知，**反向段不重叠**（一上一下）。真正会产生重叠的是两类：

> **规则 E1｜同向重复合并（必做）**
> 把所有段按**有向对** `(stop_id_from, stop_id_to)` 聚合：同一有向对只渲染一条弧线，`trips` = 该有向对的通行次数。
>
> 例：A→B→A→B→A 的序列产生 4 条原始段：`(A,B)`×2、`(B,A)`×2 → 合并为 2 条弧（一条下弧、一条上弧），`trips` 各为 2。

> **规则 E2｜近似重合合并（推荐默认开）**
> 两个**不同**的停留点可能在空间上几乎重合（例：上午在甲地停 2 小时、外出后下午又回甲地停 1 小时，因中间离开而被切成两个停留点）。
> 此时 `(甲₁,B)` 与 `(甲₂,B)` 两条弧会几乎叠在一起。
> 判据：若两条弧的**起点屏幕距离**与**终点屏幕距离**均 < 8 px（按当前缩放的屏幕像素），视为重合，合并为一条并累加 `trips`。
>
> 注：判据用屏幕像素而非米制，是为了让去重强度**随缩放自适应**——放大后两点分开，就不再合并（符合直觉）。

**去重的执行时机**：在「停留点序列 → 段」生成之后、写入 GeoJSON 之前，纯前端完成（后端只做 E1 的原始计数，前端做 E1+E2 的最终渲染决策）。

> 说明：后端在响应里给出去重后的段（含 `trips`）便于统计与测试；前端可基于当前屏幕坐标再做 E2，并把 E1 的视觉表达（线宽）叠加。

**`trips` 的视觉表达**：

| trips | 线宽系数 | 不透明度 | 悬停卡片 |
|---|---|---|---|
| 1 | 1.0 | 0.62 | 「1 次」 |
| 2–3 | 1.25 | 0.74 | 「N 次」 |
| 4–9 | 1.5 | 0.84 | 「N 次」 |
| ≥ 10 | 1.75 | 0.92 | 「N 次」+ 强调色 |

### 5.4 曲率系数 k

| k 取值 | 视觉效果 |
|---|---|
| 0.10 | 近乎直线，弧感弱 |
| 0.16–0.22 | 清晰弧形，克制 |
| 0.30–0.35 | 弧感强烈，短线可能过弯 |

**推荐方案：自适应曲率**

```
k = clamp(0.22 × (180 / screenLen), 0.14, 0.34)
```

其中 `screenLen` 是该段两端点的屏幕像素距离（用当前缩放下的经纬度 → 像素换算，或直接调用地图引擎的投影函数一次）。

| 场景 | screenLen | k | 效果 |
|---|---|---|---|
| 同城短段 | 60 px | 0.34（上限） | 短线也能看清弧度 |
| 中等段 | 180 px | 0.22 | 标准弧 |
| 跨省长段 | 700 px | 0.14（下限） | 避免"拱到天上" |

### 5.5 动效规范（F-5）

三层动效，全部受 `prefers-reduced-motion` 控制（该媒体查询关闭时全部禁用，直接静态显示）。

**第一层｜入场生长（主效果）**

| 项 | 规格 |
|---|---|
| 效果 | 每条弧从起点"生长"到终点（线像被画出来） |
| 时长 | 单条 0.6–1.2 s（按弧长归一化：长弧慢、短弧快） |
| 错峰 | 按段的时间顺序，每条延迟 40 ms（最多累计 1.2 s，超过则压缩间隔） |
| 实现（推荐） | MapLibre `line-gradient` + `line-progress`：source 开 `lineMetrics: true`，用 `requestAnimationFrame` 把 progress 从 0 推到 1；线色渐变在 progress 处"截断" |
| 实现（备选） | GSAP 驱动自定义 canvas overlay（视觉自由度更高，但要自己做投影同步，段数多时掉帧） |

**第二层｜常驻微动效（可选，默认开）**

| 项 | 规格 |
|---|---|
| 效果 | 沿弧线缓慢流动的柔和光带（或虚线相位流动），暗示"运动" |
| 周期 | 2.5–4 s 一轮（随机相位错峰，避免所有线同时闪） |
| 实现 | 逐帧更新 `line-dasharray` 相位（`[0.6, 1.4]` 基础节奏） |
| 降级 | 段数 > 260 或帧率 < 45 fps 持续 1 s → 自动降级为静态（并记忆本次会话，不反复试探） |

**第三层｜交互反馈**

| 交互 | 反馈 |
|---|---|
| 悬停某条弧 | 该弧加粗 30% + 提亮；显示卡片（起讫地名、次数、时间窗）；其余弧降低不透明度至 0.35（聚焦） |
| 点击某条弧 | 选中态：该弧持续加粗 + 两端点脉冲 2 次；（可选）联动时间轴高亮对应时段——**本期不做联动，见 U-5** |
| 悬停端点 | 显示该停留点卡片（地名、张数、停留时间窗、代表缩略图）；点击不动作（避免与簇点击冲突） |
| 关闭开关 | 全部线性淡出 0.25 s 后移除图层 |

## 6 数据与接口设计

### 6.1 新增端点：`GET /geo/footprint`

**参数（与 `/geo/clusters` 保持同款语义，前端零成本复用）**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `min_lng` `min_lat` `max_lng` `max_lat` | float | 是 | 视野包围盒，**WGS-84** |
| `zoom` | int | 是 | 当前地图缩放（决定网格粒度） |
| `from` `to` | RFC3339 | 否 | 时间范围（闭区间，与时间轴一致） |
| `kind` | enum | 否 | `all` / `photo` / `video` / `pano`（缺省 = all，不下发） |

**响应（JSON）**

```json
{

    {
      "lng": 116.4074, "lat": 39.9042,
      "place": "北京市东城区",
      "first_at": "2024-03-02T08:12:00Z",
      "last_at":  "2024-03-02T18:40:00Z",
      "count": 42,
      "cover_id": "01HV..."
    }
  ],

    {

      "trips": 3,
      "first_at": "2024-03-05T09:00:00Z",

  }

```

> 坐标按 `provider=amap` 转 GCJ-02（与簇、条目一致）；`from`/`to` 为 `stops` 数组下标。

### 6.2 SQL 范式（可直接落地）

```sql
WITH pts AS (
  SELECT ST_X(gps) AS lng, ST_Y(gps) AS lat, taken_at,
         ST_SnapToGrid(gps, $g)                 AS cell,
         id, place, has_thumb
  FROM media
  WHERE gps IS NOT NULL
    AND deleted_at IS NULL
    AND gps && ST_MakeEnvelope($1,$2,$3,$4,4326)
    AND <可见性谓词>
    AND taken_at IS NOT NULL            -- ← H-2：必须自补
    AND <时间范围>                       -- ← appendTimeRange
    AND <类型筛选>                       -- ← appendKind（'all' 时不加）
  ORDER BY taken_at, id
  LIMIT 5000
),
marked AS (
  SELECT *, CASE WHEN cell IS DISTINCT FROM
                  lag(cell) OVER (ORDER BY taken_at, id)
              THEN 1 ELSE 0 END AS is_new
  FROM pts
),
grp AS (
  SELECT *, sum(is_new) OVER (ORDER BY taken_at, id) AS g
  FROM marked
),
stops AS (
  SELECT g,
         ST_X(ST_Centroid(ST_Collect(gps)))  AS lng,
         ST_Y(ST_Centroid(ST_Collect(gps)))  AS lat,
         min(taken_at) AS first_at,
         max(taken_at) AS last_at,
         count(*)::int AS cnt,
         (array_agg(place ORDER BY taken_at DESC))[1] AS place,
         (array_agg(id    ORDER BY taken_at DESC))[1] AS cover_id
  FROM grp
  GROUP BY g
  ORDER BY first_at
  LIMIT $max_stops
)
SELECT * FROM stops;
```

**注意**（实现注记，需写进代码注释，避免后来者踩）：

1. `baseCond` 返回的是 `[]string` + `[]any`，**占位符编号必须紧接其后**——同包 `appendTimeRange` / `appendKind` 按 `len(args)` 续编，编号错位只在运行期报 `expected N arguments`。
2. `ST_SnapToGrid(gps, $g)` 的参数 `$g` 是 `GridSize(zoom)`，与簇聚合**同一函数**，保证视觉同源。
3. 组内 `array_agg(... ORDER BY taken_at DESC)[1]` 取"最近一次的取值"；若该列为空（地名缺失）需 COALESCE 处理，避免返回 null 字符串。
4. `LIMIT 5000` 是**点列**保护；若需等距抽样（§4.4），在 `pts` 里用 `row_number() % step` 实现，并把 `truncated` 透传给响应。

### 6.3 段生成放后端还是前端

| 选项 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 后端生成段 | 响应自洽、便于断言测试 | 去重规则（尤其 E2 的屏幕像素判据）是**视觉决策**，需要前端 zoom 与屏幕尺寸，后端做不了 E2 | **采用**：后端只做 E1（有向对聚合 + trips + 时间窗），E2 由前端叠加 |
| 前端从 stops 生成 | 灵活、可即时调参 | 重复实现（后端统计与前端渲染可能不一致） | 作为渲染兜底路径保留 |

**推荐分工**：后端返回 `stops` + `segments`（E1 后）；前端按需叠加 E2，并在渲染前做一次"零长度段剔除"。

### 6.4 单测与守卫更新清单

| 项 | 内容 |
|---|---|
| H-1 守卫 | `media_store_visible_test.go`：`FROM media` 计数 5 → **6**（新增足迹查询）；并补「足迹查询在 userID 为空时返回空」的可见性用例 |
| 新增单测 | ① 空结果；② 单点（0 段）；③ 两点一线（1 段）；④ 往返 A→B→A（2 段、trips 各 1）；⑤ 同格合并（多张同格 → 1 点）；⑥ 时间倒序输入（乱序点列经 ORDER BY 后仍正确）；⑦ 跨格边界（相邻格点不合并）；⑧ `truncated` 置位；⑨ `kind` 筛选生效；⑩ 时间范围生效（闭区间边界值） |

### 8.4 空态与提示

| 情形 | 表现 |
|---|---|
| 开关刚开、无数据 | 地图中央轻提示条（非模态）：「当前范围没有带位置的照片」，2.5 s 淡出；开关保持开启 |
| 只有一个停留点 | 提示：「当前范围只有一个地点，无法连线」；显示该端点标记 |

### 8.5 与现有视觉语言的一致性

- 所有颜色取自已确认的 Morandi 方案色板（雾蓝灰、米白、赭金、暖褐）；
- 卡片、圆角、阴影、字重与时间轴气泡、簇卡片**同源**；
- 动效缓动沿用 `power2.out` 系（与时间轴入场一致）；
- 不使用 emoji、不用渐变填充线（保持克制的数据可视化气质）。

### 10.2 待裁决事项

| 编号 | 事项 | 推荐口径 | 备选 |
|---|---|---|---|
| U-1 | `Δlng = 0`（正南北）时的弧向 | 按"从左往右"→ 下弧（规则单一） | 按 Δlat 决定（北向走右弧），规则更复杂但方向感更"物理" |
| U-2 | 近似重合合并（E2） | 默认开（阈值 8 px，随缩放自适应） | 默认关（只做 E1），避免"线看似变少"的困惑 |

| U-4 | 常驻微动效（流光） | 默认开，段数超限自动降级 | 默认关（更克制，性能最稳） |
| U-5 | 点击弧线是否联动时间轴高亮 | 本期不做（避免与拖拽框选语义冲突） | 做（点击后时间轴高亮该段时间，交互更强但复杂度上升） |
| U-6 | 足迹是否进分享页 | 不进（公开面暴露行动轨迹） | 由分享创建者显式开启（复杂度与隐私风险都上升） |
| U-7 | 端点是否显示代表缩略图 | 不显示（保持"串珠"简洁）；悬停卡片显示 | 显示（更丰富，但端点小圆上放缩略图会与簇混淆） |

### 13.2 原型的技术诚实性说明

原型中的弧线**不是示意图，而是真实算法的运行结果**：

- 投影：等距柱状 + 按中心纬度做米制校正（与 §5.1 一致）；
- 弧线：米制空间求单位法线 → 方向规则 D（`dx ≥ 0` 向南凸）→ 自适应曲率 `k = clamp(0.22·180/screenLen, 0.14, 0.34)` → 二次贝塞尔采样 26 点；
- 去重：地点身份归一 → 有向对聚合（规则 E1）→ 屏幕距离判据（规则 E2）；
- 因此原型里的每一条弧线走向、梭形开合方向、线宽分级**都可以直接作为实装验收的比对基准**，实施阶段可将该函数原样移植。

唯一为演示而人为处理的两处（已在原型界面注明）：

1. VIEW.33 的「原始 5 条」与「E2 近似重合」两格，把**完全重合**的弧线横向错开 14 px / 8 px 显示——否则多条线重叠在一起肉眼无法区分；
2. VIEW.31 的底图为 Morandi 抽象化示意（非真实高德瓦片），但坐标与投影比例真实。
