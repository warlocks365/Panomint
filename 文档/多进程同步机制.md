# 多任务进程同步机制 v1.0

> 生效：2026-08-25 ｜ 适用：本项目所有并行任务进程（本会话、其他 WorkBuddy 会话、后台专家 agent）
> 目标：文件修改不交叉、代码提交不冲突、进度状态可共享。

---

## 一、文件修改锁定策略（区域所有权）

### 1. 区域划分（写权限互斥）

| 区域 | 所有者 | 规则 |
|------|--------|------|
| `src/backend/internal/<pkg>/` | 领取该包任务的进程 | 一个包同一时刻只允许一个进程写 |
| `src/backend/cmd/api/main.go` | **主线（项目总监）独占** | 任何端点挂载由进程提交 diff 给主线合入 |
| `src/backend/go.mod / go.sum` | 先到先得 + 立即 `go mod tidy` | 持锁期间禁止他人 tidy；完成后发通知 |
| `src/frontend/src/views/<X>View.vue`、`components/<域>/` | 领取该视图任务的进程 | 严格隔离，禁止越界 |
| `src/frontend/src/router/index.js`、`layout/AppShell.vue`、`api/`、`stores/` | **主线独占** | 路由/外壳由主线预注入或合并 |
| `文档/` | 追加型安全，修改型需协调 | 新文档自由创建；改他人文档先沟通 |
| `docker-compose.yml`、`.env*` | **主线独占** | 基础设施变更单点控制 |
| `.workbuddy/memory/` | 追加-only | 禁止改写历史条目（append-only 纪律） |

### 2. 共享文件修改流程
1. 需要改共享文件 → 先发「锁定声明」（写入当日 memory 日志一行：`[LOCK] <文件> by <进程> <时间>`）
2. 修改 + 验证（build/vet 通过）
3. 写 `[UNLOCK] <文件>` 并通知依赖方
4. 锁持有上限 30 分钟；超时他人可接管（在日志注明接管原因）

### 3. 主线裁决
冲突无法自行消解时，以主线（项目总监会话）判定为准，依据：任务优先级 > 先声明锁 > 代码质量。

## 二、代码提交冲突处理规则

### 1. 当前凭据状态（重要）
- GitHub MCP token 对私有仓库 `warlocks365/Panomint` **不可见**（fine-grained 权限限制）
- 本地 git CLI **无交互凭据**（ls-remote 提示输入用户名，非交互环境失败）
- 另一进程（建仓进程）持有可用凭据
- **规则：在凭据打通前，所有进程只做本地 commit，不做 push；push 统一由建仓进程或凭据补齐后执行**

### 2. 提交纪律
- 提交粒度：一个任务/修复一个 commit，消息格式 `<type>: <描述>`（feat/fix/docs/chore/refactor）
- 提交前必须：`go vet ./... && go build ./...`（后端）或 `npm run build`（前端）通过
- 禁止提交：`.env`、凭据、二进制产物（`bin/`、`dist/`、`node_modules/`、`testdata/`、`data/`、`.scratch/`）——已在 `.gitignore` 兜底
- 大文件（>10MB，如 streams8k 视频）禁止入库

### 3. 合并冲突处理（凭据打通后）
- push 前必须 `git pull --rebase origin main`
- rebase 冲突：先读冲突双方上下文，保留「后声明锁」一方的语义，无法判断时升级主线裁决
- 禁止 `push --force`（main 分支保护）
- 每日收尾由当值进程 rebase 一次，保持本地与远端偏差 < 5 commits

## 三、进度状态共享方式

### 1. 单一事实来源
- **任务看板**：`.workbuddy/memory/YYYY-MM-DD.md`（当日日志，append-only）
- **长期状态**：`文档/工作日志_交接版.md`（阶段级快照，主线维护）
- **坑位表**：`.workbuddy/memory/pitfalls.jsonl`

### 2. 状态标记约定
```
[CLAIM]  <任务> by <进程> <时间>     —— 任务领取（开工前必须写）
[DONE]   <任务> by <进程> <时间>     —— 完成 + 验证方式一行
[BLOCK]  <任务> 原因                  —— 阻塞 + 依赖
[LOCK]/[UNLOCK] <文件>               —— 共享文件锁
```

### 3. 进程启动检查清单（每次开工前必做）
1. 读 `文档/工作日志_交接版.md` 最新状态
2. 读当日 + 昨日 memory 日志（看 CLAIM/DONE/LOCK 标记）
3. `git status` + `git log --oneline -5` 确认代码基线
4. 确认自己任务的文件区域无人持有锁
5. 写自己的 `[CLAIM]` 标记后再动手
