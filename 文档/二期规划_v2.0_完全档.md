## 一、功能 1 深化：24 种语言的真实成本与字体障碍

### 1.1 🔴 关键障碍：民族文字需要专用字体文件

**这是 24 语言计划里最大的隐性成本，必须先说清。**

浏览器渲染民族文字依赖**系统已安装的字体**。现实情况：

| 文字 | 常见系统（Windows/macOS/移动端）是否自带 |
| --- | --- |
| 蒙古文（传统） | ⚠️ **多数系统不带**，需 `Noto Sans Mongolian` 等 |
| 藏文 | ⚠️ 部分系统不带，需 `Noto Serif Tibetan` |
| 维吾尔文 | ⚠️ 阿拉伯字母变体，需 `Noto Naskh Arabic` |
| 朝鲜文 | 🟡 通常有（Nanum 系列） |
| 壮文 | 🔴 **几乎不带** |
| 傣文、彝文、纳西文、景颇文、佤文、拉祜文、哈萨克文、柯尔克孜文、乌孜别克文、塔塔尔文、锡伯文、俄罗斯文、苗文 | 🔴 **多数不带** |

**若不解决**：用户切到「藏文」后界面会显示**方框豆腐块**（`□□□`），这是**灾难级的体验事故**。

**解决方案（三选一）**：

| 方案 | 做法 | 成本 | 评估 |
| --- | --- | --- | --- |
| **A. 字体按需加载** | 语言包携带所需 `@font-face`，切到该语言时才下载 | 每个字体 200KB~1MB（Noto 系），**不占服务器磁盘** | ✅ **推荐** |
| B. 打包进前端 bundle | 24 种字体全进 dist | ❌ **20MB+**，且首屏加载变慢 | ❌ 排除 |
| C. 服务端字体代理 | 下载后缓存到本地磁盘 | 占服务器磁盘 + 带宽 | 🟡 备选（若 CDN 不可用） |

**决策：方案 A。** 语言包（JSON）里带 `fonts[]` 声明，切换语言时按需 `FontFace` 加载。

⚠️ **字体许可**：Noto 系列是 **SIL OFL 1.1**（可商用/可再分发 ✅），但**必须逐个核实**。
禁止使用许可不明的字体（如某些国内商业字体）。

**验收标准**：切换到每种语言后，**所有界面文案无豆腐块**（用 e2e 逐语言截图 + 像素检测）。

### 1.2 权威的 19 种清单（已查证）

来源：福建省人民政府网《少数民族的语言文字有哪些》+ 广西民族报网《广西壮族自治区少数民族语言文字工作条例条文解读》

## 三、功能 6 深化：电子相册的图片/体积上限与 3D 立体模板

### 3.1 你的要求

> 限制单相册安全图片上限和体积上限（要华丽的预制电子相册模板，包括 3D 立体相册等）

### 3.2 上限的具体数值（**已实测校准**，非估算）

**实测数据**（115，ffmpeg 5.1.9）：

```
4K 原图（PNG）        839 KB
  ↓ scale=1920 + JPEG q4
1920 JPEG            160 KB        ← 压缩到 19%
  ↓ base64 编码（固有开销 +33%）
单张 base64           214 KB
  ↓ × 20 张
20 张 base64          4.2 MB
  ↓ × 200 张
200 张 base64          40 MB        ← 比预估的 100MB 宽松得多
```

**浏览器现实阈值**（经验值，需实测校准）：

| 端 | 可接受上限 | 表现 |
| --- | --- | --- |
| Chrome 桌面 | 100 MB | 100MB 可打开，首屏解析变慢 |
| Safari 桌面 | 200 MB | 约 200MB 开始告警 |
| **iOS Safari** | **50 MB** | 约 50MB 明显卡顿（单页内存上限约 1GB） |

**最终建议值**：

| 限制 | 建议值 | 依据 |
| --- | --- | --- |
| **单相册图片数上限** | **200 张** | 实测 200 张 base64 仅 **40MB**，桌面与移动端都可接受 |
| **单张导出最长边** | **1920 px**（可配置 3840） | 实测 1920px 后单张 160KB |
| **单相册 HTML 上限（桌面）** | **100 MB** | 有 2.5 倍余量（实测 40MB） |
| **单相册 HTML 上限（移动端）** | **40 MB** | iOS Safari 50MB 卡顿线，留余量 |
| **超限行为** | 🔴 **明确报错 + 三个选项**（降质量 / 减页数 / 改用文件夹导出），**绝不静默截断** | 静默截断 = 数据丢失 |
| **单页最多图片数** | **9 张**（九宫格） | 超过 9 张排版失控 |

⚠️ **移动端更严格**：若目标包含手机，建议 **HTML 上限降到 40MB**（前端根据 `navigator.userAgent` 提示「建议用桌面浏览器打开」）。

**降级策略**（自动，用户无感）：
```
预估体积 > 100MB  →  自动降 quality 到 0.75
仍 > 100MB        →  降到 0.68
仍 > 100MB        →  提示用户选择（不自动降，避免画质过差）
```

### 3.3 「华丽预制模板」的规格

**这是模板的设计标准，我给量化要求**（避免做出来是「简陋」水平）：

| 维度 | 要求 |
| --- | --- |
| 视觉层数 | **≥3 层**（背景相纸/纹理 → 装饰元素 → 照片 → 前景装饰），产生**景深感** |
| 阴影 | 必须有（照片投影是「立体感」的来源），禁止纯平铺 |
| 配色 | 每模板一套**和谐色板**（含强调色），不得用 P0 禁止的紫粉渐变 |
| 动效 | 翻页/切换有转场（时长 300-800ms），不得是「硬切」 |
| 字体 | 中文用衬线/手写感（艺术字体），**须随模板内嵌字体子集**（避免离线时字体缺失） |
| 数量 | 首批 **8 个**（覆盖：极简/复古/现代/童趣/婚礼/旅行/商务/3D） |

⚠️ **字体内嵌的技术点**：中文字体完整内嵌是 5-10MB。方案：
- 模板只用 **200-300 个字符子集**（标题、日期、常用词）→ 子集化后约 30-80KB
- 用 `fonttools subset` 离线生成，模板包里预置
- 导出时若用户填了子集外的字 → **回退到系统字体**并提示

### 3.4 3D 立体相册的技术方案

你特别提到 3D，这是电子相册最「值钱」的部分。三种实现路径：

| 方案 | 技术 | 体积 | 视觉 | 判定 |
| --- | --- | --- | --- | --- |
| **A. CSS 3D 翻页** | `perspective` + `rotateY` + `preserve-3d` | **0 KB**（原生） | 好（有真实透视） | ✅ **主力** |
| B. Three.js 真 3D 书 | WebGL 书页模型 + 光照 | **~600KB**（内嵌） | 最佳 | 🟡 增强档（可选） |
| C. 伪 3D（缩放+阴影） | `scale` + `box-shadow` | 0 KB | 弱 | ❌ 不够「立体」 |

**建议：A 为主 + B 为可选增强**

- **默认模板用 A（CSS 3D）**：零体积、离线可用、浏览器兼容好
- **「3D 精品」模板用 B（Three.js）**：需要内嵌 three.js（压缩后约 600KB），
  ⚠️ 但**只内嵌用到的模块**（`WebGLRenderer` + `Scene` + 纹理平面），
  用 `rollup` tree-shaking 后约 150-200KB
- ⚠️ **CSP 问题**：项目已启用 CSP，WebGL 需 `worker-src blob:`（**已有放行**），
  但 three.js 本身不需要额外域名（无外链资源）→ **CSP 兼容**

**3D 交互设计**：
| 交互 | 实现 |
| --- | --- |
| 拖拽翻页 | 鼠标/触摸拖动 → 跟手旋转，松手回弹或翻页 |
| 书页卷曲 | CSS 3D 的 `rotateY` + `transform-origin: left` + 渐变阴影 |
| 惯性 | 快速拖动后按速度判定翻 1 页或 2 页 |
| 光标跟随高光 | 径向渐变叠加层跟随鼠标（提升质感明显） |

### 3.5 电子相期限值（实测校准后）

| 限制 | 值 | 备注 |
| --- | --- | --- |
| 单相册图片数 | **≤200** | 实测 base64 后 40MB |
| 单 HTML 体积 | 桌面 **≤100MB** / 移动 **≤40MB** | 前端按 UA 提示 |

## 五、功能 7 结论：广告移除

**广告从规划中移除**（非推迟，是不做）。理由备查（若将来有人问）：

1. 广告会让项目从「干净的自托管工具」变成「塞满广告的网站」—— 价值观倒退
2. 自托管用户群小、点击率低，**收益远低于维护成本**
3. 引入广告 SDK 与**已启用的 CSP 冲突**（需开第三方域白名单）
4. 广告 SDK 多为闭源，**商业使用条款需逐个核实**，与项目开源定位存在冲突可能
5. PhotoPrism 的 Plus 模式已证明「社区功能收费」会引发反弹

**赞助功能**（2.5 d）保留，且**不做付费解锁功能**——只做「赞助徽章 + 感谢名单」。
