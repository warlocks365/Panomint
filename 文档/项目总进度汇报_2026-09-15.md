## 三、当前阶段（T6.2「存储与算力分离」）交付明细

这条线的起点是：**`compute_nodes` 是 DDL 里一张零引用的空表，`transcode_jobs.node_id` 恒为 NULL**。
现在它是一条完整可用的链路：

| # | 能力 | 提交 | 关键设计取舍 |
|---|---|---|---|
| 1 | **双认证平面** | `5e4398e` | 管理端走 JWT + `admin:system`；节点侧走独立 `AgentAuth`（按 token 的 **sha256** 校验）。**不复用 JWT** —— 节点无 user_id/角色，且需要「按节点吊销/轮换」的粒度 |
| 2 | **状态锁** | `5a68b60` | 修掉「新登记节点永远无法 online」；引入 `status_locked` 区分「初始 offline」与「管理员强制 offline」 |
| 3 | **心跳与任务执行解耦** | `d2e2a4b` | ⚠️ 原实现把执行与心跳耦合在同一个 tick（`wg.Wait()`）→ **跑得比离线阈值更久的长转码会让仍在干活的节点被判 offline**，其任务被回收给别的节点 → 两节点写同一份产出。这是必须先修的前置缺陷 |
| 4 | **离线超时任务重派** | `d2e2a4b` | 判据是**节点心跳**而非任务时长（阈值 2×offlineAfter）→ 长转码不会被误回收；**惰性触发**于 Poll，不引入定时任务 |
| 5 | **执行器接真实 ffmpeg** | `5740bb7` | 抽出**无 DB 依赖**的 `TranscodeHLS`，控制端与节点**共用同一份** ffmpeg 调用（两处各写一份必然漂移）；未知 kind **显式失败** |
| 6 | **明文令牌列删除** | `7136fbc` | 迁移 00021 DROP `agent_token`（清空≠删除：备份/只读副本残留可冒用凭据） |
| 7 | **认领次数上限** | `27f3aab` | 迁移 00022 `attempts`；达上限判 failed 而非永远 pending |
| 8 | **NVENC 接口 + 自动回退** | `39253e4` | 硬编不可用**自动回退软编**，不让环境问题伪装成任务失败 |

## 四、质量与安全：本轮**挖出并修掉的真实缺陷**

这一节比功能清单更能说明进度质量。以下都是**实测复现 → 修复 → 复验**，不是推测：

| # | 缺陷 | 性质 |
|---|---|---|
| 1 | 语义搜索的**并集分支绕过空间可见性** | 🔴 **越权**：可见媒体数为 0 的用户能搜到他人个人空间照片（实测 12 行 → 0 行）。已具名化可见性条件并钉成测试断言 |
| 2 | `compute_nodes` 触发器依赖**不存在的 `updated_at` 列** | 🔴 **阻断**：任何 UPDATE 都报错，而心跳/上下线/令牌轮换全是 UPDATE —— 这正是该表长期零引用的真因 |
| 3 | 新登记节点**永远无法 online** | 🔴 三因叠加；引入状态锁修复 |
| 4 | **长任务挡住心跳 → 健康节点被判离线 → 任务被抢** | 🔴 会产出互相覆盖 |
| 5 | `01-schema.sql` 缺 4 列却建触发器 | 🟠 **同类隐患**：手工全量重置会原样再造缺陷 2；已补齐 + 加回归测试 |
| 6 | 文档/库结构漂移（DDL 文档同样缺列） | 🟠 已修，否则照文档建库即复现 |
| 7 | `AMAP_KEY` 未传给 api 服务 | 🟠 症状是"地图搜索恒降级"，看着像 Key 无效；真因是 compose 漏传变量 |
| 8 | nginx 反代**漏新前缀**（`map`/`bandwidth`/`compute-nodes`） | 🟠 同一类坑踩了 **3 次** → 纪律已写入手册 |
| 9 | 人物意图闸门阈值过松（`similarity('雪','雪景')=0.25` 会杀掉整个语义分支） | 🟠 已收紧并加固 |
| 10 | 标签接口 10 项缺陷（`confirmed:false` 被忽略、`LIMIT 100` 截断、`rotate` 覆盖写等） | 🟠 已全修 + 全量验证 |

另：**README/文档与实现的偏差**也已回填（PRD/TDD 从云端重新导出并合并了我方 9 处勘误）。
