## 一、数据模型设计

### 1.1 迁移（新增 `migrations/00045_media_metadata_edit.sql`）

```sql
-- Job000143：媒体元数据可编辑（只改库内数据，不动原媒体文件）
--
-- 背景：media.place 自 v1.x 起装的是高德逆地理的 formatted_address
--      （如「北京市东城区景山前街 4 号」），并非短地名，导致：
--        1. 「拍摄地」与「详细地址」两个概念挤在一列，无法按粒度筛选/展示；
--        2. VARCHAR(128) 对长地址偏紧。
-- 本迁移：place 语义收敛为「短地名」，address 承载「详细地址」。

-- 1.1 新增 address 列
ALTER TABLE media ADD COLUMN IF NOT EXISTS address TEXT;

-- 1.2 place 放宽到 256（短地名用不到 128，但兼容历史脏数据与手工输入）
ALTER TABLE media ALTER COLUMN place TYPE VARCHAR(256);

-- 1.3 数据迁移：把现有 place 的详细地址内容搬到 address，place 留空待重填。
--     判定依据：逆地理编码的 formatted_address 几乎总含路/号/街/巷等细节词，
--     而短地名（景点/商圈/行政区名）不含。用启发式而非全量搬迁，避免把
--     已经正确的短地名误搬。
UPDATE media
SET address = place
WHERE place IS NOT NULL
  AND place <> ''
  AND (
        place LIKE '%路%' OR place LIKE '%号%' OR place LIKE '%街%'
     OR place LIKE '%巷%' OR place LIKE '%大道%' OR place LIKE '%区%'
     OR length(place) > 24
      );

-- 1.4 同步清空已搬迁的 place，避免同一份内容两列重复
UPDATE media SET place = NULL
WHERE address IS NOT NULL AND place = address;

-- 1.5 审计：迁移不改历史数据（place 的原值已在 address 留存）
COMMENT ON COLUMN media.address IS
  '详细地址（用户可编辑，Job000143）。由地图搜索候选带入或手工填写。仅相册系统数据，不写回原媒体文件。';
COMMENT ON COLUMN media.place IS
  '拍摄地短地名（用户可编辑，Job000143）。反向地理编码的 formatted_address 已迁至 address。';
```

**兼容性**：
- 迁移**幂等**（`IF NOT EXISTS` + 启发式条件稳定）
- 迁移**可回滚**（新增列可 `DROP COLUMN`；place/address 的搬迁是复制而非移动，回滚只需 `UPDATE media SET place = address WHERE address IS NOT NULL`）
- 不动 `gps` / `taken_at`（无需迁移）

### 1.2 字段语义（实施后）

| 字段 | 语义 | 示例 | 来源 |
| --- | --- | --- | --- |
| `gps` | WGS-84 经纬度 | `116.397, 39.918` | EXIF / 地图选点 / 搜索候选 |
| `place` | 拍摄地**短地名** | 故宫博物院 | 搜索候选 `name` / 手工输入 / 逆地理 `township` |
| `address` | **详细地址** | 北京市东城区景山前街 4 号 | 搜索候选 `address` / 手工输入 / 逆地理 `formatted_address` |
| `taken_at` | 拍摄时间 | 2026-08-15 14:30 | EXIF / 手工输入 |

### 1.3 坐标系（**关键正确性约束**）

| 来源 | 坐标系 | 处理 |
| --- | --- | --- |
| EXIF GPS | WGS-84 | 直接存 |
| 高德地图选点 | **GCJ-02** | 前端提交前 `GCJ02ToWGS84` 转 WGS-84 |
| 高德搜索候选 | **GCJ-02** | 服务端 `GCJ02ToWGS84` 转 WGS-84 后落库 |
| Nominatim 候选 | WGS-84 | 直接存 |

> 库内 `gps` 是 `geometry(Point,4326)`，**必须存 WGS-84**（地图页 `geo/clusters` 与 `geo/items` 按此聚合）。当前 `/map/search` 返回的候选**未做转换**（`MapCandidate.Lon/Lat` 是上游原生），本次在**服务端落库前**统一转换。

## 二、后端设计

### 2.1 扩展 `MapCandidate` 增加 address

`internal/geo/mapsearch.go`：

```go
type MapCandidate struct {
    Name     string  `json:"name"`
    Lon      float64 `json:"lon"`
    Lat      float64 `json:"lat"`
    Provider string  `json:"provider"`
    // Job000143：详细地址（高德 formatted_address / Nominatim display_name）。
    // 供媒体元数据编辑使用；缺失时前端回退为仅填 name。
    Address  string  `json:"address,omitempty"`
}
```

高德 `ForwardHit` 同步加 `Address`（上游 `address` 字段 / `formatted_address`）。

### 2.2 扩展 `PATCH /media/:id`

**位置**：`internal/media/write_handlers.go:180`

**白名单从 2 项扩到 5 项**（保持 `DisallowUnknownFields` 严格策略）：

```go
var req struct {
    Notes    *string         `json:"notes"`
    Edits    json.RawMessage `json:"edits"`
    // Job000143：元数据编辑（三态语义：nil=不动）
    TakenAt  *string         `json:"taken_at"`  // RFC3339
    Place    *string         `json:"place"`
    Address  *string         `json:"address"`
    Lat      *float64        `json:"lat"`
    Lng      *float64        `json:"lng"`
}
```

**语义约定（逐项明确，避免歧义）**：

| 请求 | 语义 |
| --- | --- |
| 字段缺席（`nil`） | **不动**该字段 |
| `""`（空串） | **清空**该字段（`place`/`address` 置 NULL；`lat`/`lng` 置 NULL） |
| 非空值 | **更新** |
| `lat`/`lng` | **必须成对出现**（只给一个 → 400，避免半截坐标污染 `geometry`） |
| `taken_at` | RFC3339 字符串，非法格式 → 400（不静默忽略） |

**坐标校验**：
- `lat ∈ [-90, 90]`，`lng ∈ [-180, 180]`，越界 → 400
- 两者都为 `""`/null → 置 `gps = NULL`
- 两者都有值 → `ST_SetSRID(ST_MakePoint($lng, $lat), 4326)`

**审计**：新增动作 `media.metadata_edit`，`detail` 记 `{fields: ["gps","place"], source: "map-search"}`。
⚠️ **不记坐标明文**（详情页 detail 要避开 hash 子串的同款纪律；坐标属半敏感位置数据）。

**权限**：`permWrite`（`media:write`）+ `checkAccess`（属主或 owner/admin，无权 → 404）——沿用现有 PATCH 的 `checkAccess` 模式。

### 2.3 新增 Store 方法

`internal/media/store.go`：

```go
// SetMetadata 更新媒体的地理与时间元数据。
// 三态：nil=不动 / 空串=清空 / 非空=更新（语义在 handler 层归一化后传入）。
// ⚠️ 只写 media 表，绝不触碰 path 指向的原媒体文件。
func (s *Store) SetMetadata(ctx context.Context, id string, m MetadataUpdate) (*Media, error)
```

内部用**单条 UPDATE + COALESCE 模式**（一次往返，避免 N 条 UPDATE）：

```sql
UPDATE media SET
    taken_at = CASE WHEN $2::boolean THEN $3::timestamptz ELSE taken_at END,
    place    = CASE WHEN $4::boolean THEN $5::varchar    ELSE place    END,
    address  = CASE WHEN $6::boolean THEN $7::text        ELSE address  END,
    gps      = CASE WHEN $8::boolean THEN $9::geometry    ELSE gps      END,
    updated_at = now()
WHERE id = $1::uuid
RETURNING <cols>
```

**为什么用 `CASE WHEN $flag` 而非 COALESCE**：`COALESCE($new, old)` 语义是「传 null 就保持」——无法表达「显式清空」。用显式 flag 参数才能区分「不动」与「清空」。

### 2.4 逆地理编码复用（选点后回填地址）

选点只给坐标，详细地址需逆地理。`AmapGeocoder.ReverseGeocode` 已实现且带 `geo_cache` 缓存（`ReverseCacheKey` 按 4 位小数）。

**但高德返回的是 `formatted_address`（完整地址），没有短地名。** 短地名的获取策略：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 搜索候选的 `name` | 用户主动搜索 → 短地名就是候选名，最准 |
| 2 | 逆地理 `formatted_address` 的行政区提取 | 地图选点 → 从地址前缀提取（`北京市` / `朝阳区`） |
| 3 | 留空 | 解析不出则让用户手填，不猜 |

> **裁决**：不为「短地名」新增高德 API 调用（`geocoding/regeo` 不返回 township 级别的短名，需另调 `district` 接口）。策略 2 用**本地字符串解析**，零额外配额消耗，失败则留空由用户填。

### 2.5 契约更新

`文档/API详细契约_v1.2.md` 补 `PATCH /media/:id` 的新字段（`DisallowUnknownFields` 是显式契约，加字段是**契约扩展**而非破坏）。

```
       系统必须弹出操作菜单且含「编辑元数据」项。
AC-12 If 用户无 media:write 权限，
       系统必须返回 404（而非 403），且不泄露媒体是否存在。
```

## 五、需你确认的三个决策点

1. **短地名提取策略**：地图选点后，用本地字符串解析从完整地址提取行政区名（如「北京市朝阳区」→「北京市」），失败则留空由用户手填。**认可这个策略吗？**（替代方案是调高德 `district` 接口拿官方短名，但多一次 API 配额消耗）

2. **长按菜单的触发方式**：桌面端右键 + 移动端长按 600ms。**移动端长按会不会与现有手势冲突？** 我查了 `MediaTileGrid` 目前无其它长按手势，理论上不冲突。

3. **是否需要批量编辑**：比如相册里选中 20 张一起改地点。当前设计是单条编辑。**要加批量吗？**（会显著增加复杂度：批量逆地理的配额、事务、部分失败处理）

### 与设计的三处偏差（均为实施中发现的问题所迫）

1. **新增 `internal/geocoord` 包**（设计未预见）：`media` 需要坐标转换，但 `geo` 反向依赖 `media`（geo→search→media），直接引用形成**导入循环**，Go 编译期直接拒绝。坐标转换是纯数学函数，拆到零依赖的独立包，`geo` 保留同名薄封装。

2. **短地名提取放在 `internal/geo` 但不改变 `/map/search` 的 `name` 语义**：设计里打算让 `name` 直接变短地名，实测会变更**地图页现有搜索的展示**（`MapSearchBox` 直接渲染 `c.name`）—— 超范围。故 `name` 保持完整地址不变，短地名提取作为**独立纯函数** `geo.ShortPlaceName()` 供需要方调用。

3. **新增 `X-Coord-Source` 请求头**：设计里说「前端提交前转换」，但前端**不知道底图用的是哪套坐标系**（换底图就错）。改为前端只声明来源、**服务端单一收口转换**。

### 通用纪律沉淀（本次踩坑产出）

1. **给缓存载荷加字段必须 bump 缓存 key 版本**：`geo_cache` 的 key 原本只含 `fwd:<provider>:<query>`，加 `Address` 字段后旧缓存命中仍缺该字段，且**清缓存前无法自愈**。已改为 `fwd:<ver>:<provider>:<query>`。
2. **「接口 200 但某字段恒为空」优先查透传链路，不先怀疑缓存**：本次 `address` 恒空，我先改缓存 key（无效），真因是**三处透传全漏**。表现相同、根因不同。
3. **e2e 探针自身出错时，功能会被误判为坏**：本次连续三次「功能失效」实为探针问题（选择器用错 `.media-tile` 而非 `.thumb`、找不存在的「信息页签」、过早探测异步渲染的元素）。**探针报错先怀疑探针**。
4. **跨组件事件字段名不一致要用 typeof 守卫**：`emit {lat,lon}` vs 接收读 `pos.lng`，弹层内显示正常而回填 NaN —— 只有断言回填值才暴露。
