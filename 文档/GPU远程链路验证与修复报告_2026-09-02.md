## 二、验证 2 一度卡住：根因不在环境，在脚本

`PROMPT-for-A.md` 第 49 行明确要求"能出报告就别去改 gpu.py"。这条规则的适用前提是**问题出在坏的 `python` 别名**。本次经对照实验证明，缺陷确实在 `gpu.py` 自身，因此适用边界不成立。

### 缺陷 1：`set VAR=value ` 的尾随空格 —— 致命，影响全部远程 Python 调用

`gpu.py:311` 的 `build_env()` 用 `" && ".join(...)` 拼接环境变量。cmd.exe 的 `set` 是**贪婪取值**，会把 `&&` 前那个空格一并吃进值里。

直接取证（`cat -A`，`^M` 为行尾 CR）：

```
修复前：PYTHONUTF8=1 ^M^M$      ← 1 后面有空格，实际值为 "1 "
修复后：PYTHONUTF8=1^M^M$
```

Python 对 `PYTHONUTF8` 做严格枚举校验（只接受 `0`/`1`/`utf8`），`"1 "` 非法 → 解释器启动即崩：

```
Fatal Python error: preconfig_init_utf8_mode: invalid PYTHONUTF8 environment variable value
```

这个变量原本是为了让远程输出走 UTF-8，结果把**所有**发往远端的 Python 调用全部打死了。

**对照实验**（同一远程解释器、同一份代码，唯一差别是变量赋值方式）：

| 调用 | 结果 |
|---|---|
| `gpu.py <py> check_torch.py` | ❌ exit 1，Fatal Python error |
| `gpu.py "set" "PYTHONUTF8=1&&" <py> check_torch.py` | ✅ exit 0，打出 RTX 3090 |

### 缺陷 2：远程命令未做 Windows 转义

`gpu.py:386` 用 `" ".join(args.command)`。argparse 的 `REMAINDER` 拿到的是**本地 shell 已剥掉引号**的 token，再 join 一次引号就永久丢失：

```
意图：python -c "import torch; print(x)"
实发：python -c import torch; print(x)
       → cmd 按 ; 断句 → Python 只收到 import
       → SyntaxError: invalid syntax
```

### 缺陷 3：B 机 PATH 上没有 `python`（已由 B 侧补 `resolve_python_alias()` 解决）

`where python` → `INFO: Could not find files`。而 `gpu.json` 里配的 `remote_python` 只在 `--doctor` 里打印，**从不参与命令替换**。所以文档里 `gpu.py python -c "..."` 这个写法在 B 上永远不成立。

> 注意：这与 A 端那个 Windows Store App Alias stub 是**两件不同的事**，不要混为一谈。

**解决方案**（B 侧于 22:29 实现，本机已实测验证）：新增 `resolve_python_alias()`，把开头的裸 `python` / `python3` / `python.exe` / `python3.exe` 换成 `gpu.json` 里的 `remote_python`。设计上刻意规避了"暗箱魔法"：

| 设计决策 | 做法 |
|---|---|
| 不让"敲的命令"和"跑的命令"无声分叉 | 每次替换都在 **stderr** 打一行 `[gpu] alias: python -> D:\gpu-runtime\venv\Scripts\python.exe` |
| 不抢 stdout | stdout 归用户程序，重定向与 CI 解析不受污染 |
| 不废掉旧写法 | 只替换**裸名字**；已带路径的一律不动，完整路径仍然有效且优先 |
| 语义不清的不猜 | `pytest` 不在替换集合内（可能指系统 pytest），文档统一写 `python -m pytest` |

**用例测试 10/10 通过**（`resolve_python_alias` 单元测试）：

|---|---|---|

**改动 1 — 顶部新增导入**


**改动 2 — `build_env()`（3 处赋值改引号形式）**

```python
def build_env(conf: dict, use_limit: bool) -> str:
    # cmd.exe's `set` is greedy: in `set VAR=1 && ...` the space before `&&`
    # becomes part of the value ("1 "). Python validates PYTHONUTF8 strictly
    # and dies with "Fatal Python error: preconfig_init_utf8_mode" on "1 ",
    # so every form here must use the quoted `set "VAR=value"` syntax, which
    # makes cmd strip the quotes and take the inside verbatim.
    bits = ["chcp 65001>nul", 'set "PYTHONIOENCODING=utf-8"', 'set "PYTHONUTF8=1"']
    if use_limit:
        frac = conf["mem_fraction"]
        bits.append(f'set "GPU_MEM_FRACTION={frac}"')
    return " && ".join(bits)
```

**改动 3 — 命令拼接改用 Windows 转义**

```python
    # args.command arrives as tokens the local shell already unquoted.
    # Joining them back with spaces loses the quoting forever, so
    # `python -c "import torch; print(x)"` turns into
    # `python -c import torch; print(x)` and cmd splits on the `;`.
    # list2cmdline re-applies Windows-style quoting per argument.
    remote_cmd = " && ".join([
        f'cd /d "{conf["remote_dir"]}"',
        build_env(conf, not args.no_limit),
        subprocess.list2cmdline(args.command),   # 原为 " ".join(args.command)
    ])
```

## 五、使用守则（修复后）

1. **直接写 `python` 即可**，与本地写法完全一致——裸 `python` 会被自动替换成 B 的真实解释器，并在 stderr 打出一行替换提示。写完整路径 `D:/gpu-runtime/venv/Scripts/python.exe` 同样有效且优先（已带路径的不做替换）。`pytest` 不替换，请写 `python -m pytest`。
2. **多行 `-c` 会静默失败**：换行符被 cmd 当命令分隔符，Python 只收到第一行，结果是 `exit=0` 但零输出——报成功却什么都没跑。多行逻辑一律写成 `.py` 文件随同步上传后执行。判据是**看 stdout 有没有预期输出**，不能只看退出码。
3. 单行 `-c` 可以正常带分号、空格、引号（`list2cmdline` 已处理）。
4. 数据集与权重放 B 本地 `D:\gpu-work\data`、`D:\gpu-work\ckpt`，走内置排除清单不同步。
5. 退出码纪律不变：**0 成功 / 1 代码 bug / 2 环境问题 / 3 用法错 / 4 本地配置未完成**；见 `ENVIRONMENT PROBLEM` 或 `SETUP INCOMPLETE` 立即停止改代码。

## 六、遗留问题：stdout 仍有一行污染（B 侧，未修）

别名替换的提示确实只走 stderr，但**分离重定向实测暴露出 stdout 上还有一行**：

```
########## STDOUT（只能有程序输出）##########
[gpu-quota] per-process vRAM cap = 50% (12288 MiB of 24576 MiB)   ← 不是用户程序的输出
exec      : D:\gpu-runtime\venv\Scripts\python.exe
device    : NVIDIA GeForce RTX 3090
########## STDERR（诊断信息归这里）##########
[gpu] alias: python -> D:\gpu-runtime\venv\Scripts\python.exe (B has no `python` on PATH)
[gpu] exit=0 elapsed=1.7s
```

来源不在 `gpu.py`，而在 **B 机 `D:\gpu-runtime\venv\Lib\site-packages\sitecustomize.py`**，该文件在解释器启动时被自动导入，用裸 `print()` 往 **stdout** 打了两处：

```python
print(f"[gpu-quota] per-process vRAM cap = {fraction:.0%} "
      f"({fraction * total_mb:.0f} MiB of {total_mb:.0f} MiB)", flush=True)
...
print(f"[gpu-quota] warning: could not apply quota: {exc}", flush=True)
```

**影响**：`gpu.py python train.py > results.txt` 时，`results.txt` 第一行会是配额提示。若下游用 stdout 做 CI 解析或结构化输出（如训练脚本打印 JSON），这一行会破坏解析。

**建议修法**（B 侧一处改动，两行加 `file=sys.stderr`）：

```python
import sys
...
print(..., file=sys.stderr, flush=True)
```

该文件只在 `GPU_MEM_FRACTION` 存在时激活，本地跑 python 时为零开销，改动风险低。因属 B 机共享 venv（B 本机还跑 llama-server 等），**未擅自修改，待确认**。
