## 一、更新摘要

### 1.1 新增：HEVC 视频「兼容播放」（实时转码兜底）

关闭 HLS 转码后，HEVC 视频在**不支持解码的浏览器**上此前只能提示换浏览器。本版本在提示旁提供**「兼容播放」**——用户显式点击后，服务端按需 ffmpeg 实时转码 720p 单档动态 HLS，不开启 HLS 转码也能播放。

- **按需触发**：仅在浏览器检测不支持且用户点击时启动，与「关闭自动转码」语义兼容（不自动转码，人工兜底）；
- **资源护栏**：720p / 1800kbps / ultrafast 单档（CPU 开销下限）、**全局并发上限 1**（第二路返回明确提示）、会话空闲 10 分钟自动回收、进程退出即清理；
- **权限同构**：与下载端点共用 `checkReadAccess` 判定（无权 404/403 同形），支持 query token（`<video>` 元素场景）；
- **进度拖动**：携带秒偏移重建转码会话（旧会话即时回收），首次缓冲约 10 秒（取决于服务器算力）。

### 1.2 新增：系统启动状态检测（A + B）

服务启动窗口（数据库迁移/容器重建）访问不再看到散乱报错：

- **B（前端 BootGate）**：路由守卫探测 `/ready`（数据库/队列/磁盘三检查），未就绪自动进入全屏等待页——显示分项就绪进度，就绪后**自动回到原目标页面**；超过 3 分钟给出排查指引（容器日志/依赖状态/磁盘空间）+ 手动重试；
- **A（nginx 兜底页）**：直接访问 API 路径遇到 502/503/504 时返回内置「系统启动中」页（限频自动重试）；对非页面请求（API/探测，Accept 不含 text/html）**保持 502 状态码**，确保前端探测与流媒体客户端能正确识别失败。

### 1.3 修复：未初始化访问相册不跳初始化向导

根因：`/setup/status` 查询在 api 未就绪瞬间失败时，路由守卫按「不可达放行」处理，用户落在相册页却进不了向导。修复：查询失败先重试一次（800ms）再判定；且 BootGate 置于守卫最前，启动窗口内根本不放行到业务路由。**实测**：模拟首次查询瞬断 → 自动重试 → 正确跳转 `/setup`。

### 1.4 修复：构建提交号显示 unknown

`build-images.sh` 支持 `APP_COMMIT` 显式注入（构建机非 git 仓库时由发版流程传入 tag 提交号），版本信息卡与 `/version` 现在显示真实构建提交。

### 1.5 兼容性与质量

- 零数据库迁移、零 API 契约变更（新增 `/media/:id/live/*` 为内部播放端点）；
- 后端单测（含 live 会话管理 7 项守卫）、媒体可见性登记守卫、全量 go test 全绿；
- UI 实测 11/11（HEVC 兼容播放全链：提示→入口→动态清单→分片→解码播放；H.264 直链回归不受影响）+ BootGate 全流程 5/5（拦截→等待页→自动回跳）；
- 验证实录：5.3GB HEVC 全景视频在无 HEVC 解码的无头 Chromium 中经兼容播放成功解码（1280×720 实时转码输出）。

## 二、部署指引

### 2.1 Docker 镜像版

```bash
# 群晖：release/docker/docker-compose.synology.yml（已指向 :1.7.2）
# 通用：compose 中 image tag 改为 1.7.2（或 latest）后 up -d
docker pull warlocks/panomint-web:1.7.2
docker pull warlocks/panomint-app:1.7.2
```

运行版本自检：设置页「版本信息」卡显示 `v1.7.2`（含构建提交号）；或 `curl http://<host>:8088/version`。

### 2.2 升级注意事项

1. **从 1.7.1 升级**：拉取 `:1.7.2`（或 `:latest`）镜像重建 web 与 app 容器即可；无迁移、无配置变更。api + 常驻 worker 共用 app 镜像需一并 recreate；index/transcode worker 镜像独立，本版未变更可不重建。
2. **兼容播放的算力预期**：实时转码单路约 1 核 CPU（4K 源更高），并发被限制为 1 路以保护宿主机；低功耗 NAS 上首次缓冲可能超过 10 秒，属预期行为。
3. **降级回滚**：image tag 换回 `1.7.1` 重建即可；无数据结构差异。
