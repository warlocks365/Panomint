## 0. 结论先行（给决策用）

1. **功能成立，且与「视频热点回忆」共用同一套骨架**：可选总开关、三种触发（手动 / 新视频自动 / 闲时段）、
   独立队列 + 独立 worker、`mediascope` 隔离、搜索按时间点跳转、分享勾选。
   建议**两者沿同一套调度与展示范式实现**，避免做成两套互不相干的机制（见 §1.3）。

2. **ASR 引擎选型已定：`whisper.cpp`（MIT）作为本地推理引擎，走独立二进制 + subprocess 调用**。
   核实结论（2026-10-10）：
   - 当前稳定版 **v1.9.3**（2026-08-20），仓库已迁至 `ggml-org/whisper.cpp`，**MIT 许可**；
   - **原生直接输出 SRT / VTT / JSON（含词级时间戳）** —— `-osrt` / `-ovtt` / `-oj -ml 1`，
     与"外挂字幕文件"的需求**逐字命中**，无需自行拼装字幕格式；
   - 后端覆盖 CPU（AVX/AVX2/AVX-512/NEON）与 CUDA / Metal / Vulkan / ROCm / OpenVINO 等，
     **CPU 与 GPU 双接口与项目既有红线一致**（配置选择而非编译期裁剪）；
   - 模型许可同样干净（Whisper 权重 © OpenAI，**MIT**）。
   备选方案与排除理由见 §8。

3. **需要你注意的是三处"用户未提出但必须做"的事**：
   - **字幕编辑必须做**（ASR 必然有错字；不能改则整个功能价值折半）——见 §3.6；
   - **时间轴偏移校正必须做**（ASR 时间戳普遍有 ±0.3–1s 漂移，长片尤甚）——见 §3.6；
   - **全景视频的字幕渲染不能用浏览器原生 `<track>`**（视频是纹理贴在球面上，标准字幕轨不生效），
     必须自研覆盖层 —— 这是本功能**最大的技术差异点与工程量点**，见 §3.5。

4. **"多语言"建议按需生成而非全量**：原文轨由 ASR 直接产出（自动检测语言，覆盖 99 种）；
   翻译轨走 LLM 编排（复用 `/agent/llm/v1`，与回忆功能的 L2 同源）。**默认只出原文轨**，
   目标语言由用户在设置里勾选（默认 1–2 个）。若默认生成 24 种语言轨，单视频翻译成本将从
   ~3k token 涨到 ~72k token（见 §8.4 成本估算）。

5. **工期估算：23 人日（P0+P1）；含 20% 返工冗余 = 28 人日**。token 估算 60–90 万
   （不含翻译运行成本，后者按配额控制）。若并入二期：**195 → 约 223 工作日**。

6. **隐私等级高于回忆功能**：语音内容可包含家庭对话、姓名、地址等敏感信息。
   设计前提：**全本地推理、默认不上传任何音频或文本到外部、默认不随分享外发、审计不含内容**（见 §6.4）。

## 1. 功能定位与命名

### 1.1 一句话定义

对相册中的视频做**本地语音识别**，产出**外挂字幕文件**（SRT / VTT，可导出、可替换、可编辑）；
支持生成**多语言翻译轨**；字幕内容可按开关参与全局搜索，命中后**跳到视频对应时间点**播放。

### 1.2 与相邻概念的边界

| 概念 | 关系 |
| --- | --- |
| **视频热点回忆**（已并入二期） | **同族功能**，非同一功能。回忆 = 用户标注的稀疏"值得重看"位置；字幕 = 机器产出的**连续覆盖全片**的文本轨。二者数据结构、生成方式、交互都不同，**不共用数据表**；但共用调度骨架、搜索分组样式、播放器时间轴跳转契约 —— 见 §1.3 |
| `media_tags` / `media.filename` 搜索（现有） | 字幕搜索是**第三类检索对象**（按时间点定位到"视频里的某句话"），与前两者并列而非替代 |
| i18n（二期 24 语言） | **解耦**。i18n 是"界面文案的多语言"，字幕是"内容的语言"。两者的语言集合、生成机制、成本模型完全不同。**不要**把字幕翻译绑到 24 语言计划上 |
| OCR 检索（二期第一批第 2 项，PP-OCRv5） | 语义互补：OCR 抓画面里的文字（招牌、字幕烧录版），本功能抓**语音**。两者可合并为"内容检索"大类，但实现独立 |
| 音频转码 / HLS | 无关。本功能只**提取**音频（ffmpeg 一条命令），不改动原文件与转码产物 |

### 1.3 与「视频热点回忆」的共用部分（架构建议）

| 共用项 | 说明 |
| --- | --- |
| 总开关范式 | 同一张设置卡片的形态：总开关 + 子项 + 生效时段 + 触发方式 + 配额 + 运行状态 |
| 任务调度 | **同一套"闲时段 + 配额 + 并发 1"调度器**（字幕任务与 AI 打点任务排队规则一致，避免两套逻辑漂移） |
| 队列纪律 | 独立队列名 `q:subtitle` + 独立 worker（核实结论：现有 index/transcode worker **不按 kind 过滤**，直接 `Handle`；见 §13 证据 E-4） |
| 播放器桥接 | **同一份**时间轴跳转契约（`?t=<ms>` 路由参数 + 全景视角恢复）。字幕功能**不需要**新增播放器桥，直接复用回忆功能建立的通道 |
| 搜索分组 | 同一套"时间轴命中"结果项样式（缩略图 + 时间 + 跳转按钮） |
| 分享勾选 | 同一处"分享内容扩展"区域（回忆标签 / 字幕轨 并列勾选） |

**协同增益（值得单列）**：字幕产出后，**回忆功能的 AI 打点质量会显著提升** ——
L2 文本编排的输入从"音频能量峰值"升级为"这里说了一句话：'囡囡你看这个！'"。
建议在实现顺序上**先做字幕、再做回忆的 AI 部分**，或至少让回忆的 L2 支持读取已存在的字幕文本
（作为可选输入）。这是"1+1>2"的排列组合，成本极低。

## 3. 功能逐项展开（含修正建议）

> 标记约定：**【保留】** 原需求可直接落地；**【澄清】** 需补充定义；**【修正建议】** 建议改变原写法，理由随附。

### S1 总开关与任务触发

**原需求**：增加一个**可选的**，可**手动触发**或**自动触发**或**按设定闲时段触发**的语音识别功能。

| 需求点 | 处置 | 说明 |
| --- | --- | --- |
| 可选（总开关） | 【保留】 | 默认**关闭**。关闭后：详情页字幕块不渲染、搜索不含字幕条目、分享不含字幕勾选；已生成的字幕文件**仍保留在存储中**且已配置的字幕仍可播放（不追溯破坏）。 |
| 手动触发 | 【保留】 | 详情页「生成字幕」按钮 + 管理页批量选择。 |
| 自动触发 | 【修正建议】 | 与回忆 R-8 同一理由：**默认关闭 + 双重限流**（单次入库最多 N 个、队列串行）。ASR 比重任务更重（CPU 上以"实时的小倍数"耗时），批量导入 100 个视频若自动排队，队列会连续占满数小时。 |
| 闲时段触发 | 【保留】 | 与回忆"生效时段"同构，**共用同一个时段配置**（默认 `02:00–06:00`），避免两个功能各配一套时段互相打架。 |
| 配额 | 【修正建议，补充】 | 新增：**单日字幕任务数上限**（默认 10 个视频；比回忆的 20 更保守，因单任务耗时更长）+ **单视频时长上限**（默认 60 分钟，超出需手动确认，防 3 小时长片阻塞队列）。 |

**任务模式（【澄清】）**：字幕任务需要"进度可见 + 可取消 + 可重排"，因此走**队列**（`q:subtitle`）而非
`facesgen` 式的清扫轮询。原因：ASR 单任务耗时可达数十分钟，用户必须看得到"正在识别 43%"，
否则会被当成卡死。**独立队列名是硬要求** —— 见 §1.3 共用项的队列纪律说明。

### S2 语音识别生成原文字幕

**原需求**：对相册视频进行语音识别。

**【澄清 —— 需要处理的五类"不合适的输入"】**（否则会浪费大量算力）：

| 情况 | 判定 | 行为 |
| --- | --- | --- |
| 无音轨（纯画面/延时摄影） | ffprobe 探测音频流 | 跳过 + 标记 `no_audio`（**不排队**，避免白跑） |
| 纯音乐（无语音） | whisper 返回空/极短文本 | 标记 `no_speech`，保留空轨记录（避免反复重跑） |
| 已有人工字幕 | 导入轨已存在且 `source='import'` | 默认**跳过 ASR**（人工字幕质量必然更高），用户可强制覆盖 |
| 极长视频（> 时长上限） | `media.duration` | 排队前拦截，提示并给"仍然生成"的显式确认 |
| 时长极短（< 10 秒） | `media.duration` | 跳过（无识别价值） |

**【澄清 —— 音频提取】**：调用 whisper 前需要 16 kHz 单声道 WAV（whisper 的输入要求）。
新增 `ffmpeg.ExtractAudioArgs()`（`-vn -ac 1 -ar 16000 -c:a pcm_s16le`），与既有 `presets.go` 的
参数构造风格一致。**中间 WAV 用完即删**（1 小时音频约 115 MB，不落地留存）。

**【澄清 —— 语言设置】**：
- 默认 `-l auto`（自动检测），检测结果写入轨记录（`lang` 字段），供搜索与展示；
- 允许用户指定源语言（`-l zh`），用于自动检测失误时的修正（如中英混杂的视频）。

### S3 多语言翻译轨

**原需求**：生成**多语言**外挂字幕文件。

**【修正建议 —— 按需生成，不默认全量】**：见 §0.4 与 §8.4。
- 默认：**只生成原文轨**。
- 翻译轨：用户在设置里勾选"目标语言"（从常用语言里选，默认建议 `en`；可加 `ja` / `ru` / `fr`，
  与 i18n 语言集合**解耦**，但 UI 上可复用同一套语言名表）。
- 也可对**单个视频**临时追加语言（详情页"添加语言"）。

**【关键设计 —— 时间轴必须保持不变】**：翻译轨**不重新识别**，而是把原文轨的句子文本送 LLM 翻译后
**回填到原时间戳**。这样：
1. 一行字幕在两种语言下时间完全对齐（切换语言时画面不跳动）；
2. 翻译失败/部分失败时可增量补（只补缺的句子）；
3. 成本 = 文本字数 × 语言数，与视频时长解耦（短视频也可能话很多）。

**【翻译质量策略（【澄清】）】**：逐句翻译会丢上下文（代词、语气），整段翻译又要重新切分时间轴。
折中方案：**滑动窗口批量翻译** —— 每次取连续 8–12 句为一组送 LLM，要求返回等长的逐句译文数组
（JSON），按序回填。窗口重叠 2 句作为上下文。这样既保时间轴又保上下文。

### S4 外挂字幕文件生成与导出

**原需求**：生成外挂字幕**文件**。

**【保留】** 且**由 whisper.cpp 原生完成**（`-osrt` 输出 `.srt`、`-ovtt` 输出 `.vtt`），
翻译轨由后端按同样格式生成。文件存储：MinIO，路径建议 `subtitles/<media_id>/<lang>.<ext>`。

**【澄清 —— 双写设计】**：

| 载体 | 职责 | 理由 |
| --- | --- | --- |
| **字幕文件**（MinIO：`.srt` + `.vtt`） | 播放器加载、用户下载、导出 | 标准格式，可被任何播放器/工具使用 —— 这正是"外挂"的本义 |
| **句子表**（PG：`subtitle_cues`） | 搜索索引、编辑界面、统计 | SQL 才能做模糊查询与分页；每次搜索去解析 SRT 文件不可行 |

**播放器引用哪个？** 统一走**文件**（`<track src="/media/:id/subtitles/:trackId.vtt">`），
句子表只服务搜索与编辑。这样"用户用自己的字幕文件覆盖"这件事天然成立（换掉文件即可）。

### S5 播放器字幕显示（**本功能最大技术差异点**）

**【澄清 —— 两类播放器必须分别处理】**：

| 播放器 | 方案 | 工程量 |
| --- | --- | --- |
| **普通视频**（`PlayerView` 内联 `<video controls>`） | 原生 `<track kind="subtitles" srclang="zh" label="中文" default>`；切换语言 = 切换 track；浏览器原生渲染 | 低（0.5 d） |
| **全景视频**（`360Player` + `usePanoEngine`，视频作为纹理贴在球面） | **原生 `<track>` 完全不生效**（视频不是普通的播放元素，而是 WebGL 纹理）。必须：① 自研 VTT 解析（或从句子表取）；② 在 canvas **之上**的 DOM 覆盖层按 `currentTime` 渲染当前句；③ 字幕位置/字号要能被用户调整（全景画面里字幕位置固定会遮挡某些视角） | 中高（2 d） |

**【修正建议 —— 全景字幕给三条实用开关】**（否则体验会差）：
1. **字幕位置**：底部居中（默认）/ 跟随视角固定（抬头时字幕仍在视野内）/ 可拖拽；
2. **字号**：三档（小 / 中 / 大）；全景画面在 VR 头显或远距离观看时需要更大字号；
3. **背景条**：字幕后加半透明底（默认开），避免浅色画面（雪景、天空）上白字看不见。

**【澄清 —— HLS 模式】**：普通视频若走 HLS（hls.js），外挂 `<track>` 仍可用（浏览器侧字幕与
媒体分发无关）。**不需要**把字幕烧进 HLS 分片（那会破坏"外挂"语义，且要重转码）。

### S6 字幕浏览与编辑

**【修正建议 —— 原需求未提，但必须做】**：ASR 的错字率即使在中英清晰语音下也有 5–15%
（专有名词、方言、口音更高）。如果字幕只能看不能改：
- 用户无法修正"囡囡"被识别成"楠楠"这类必然发生的错误；
- 家庭视频里最重要的恰恰是**人名与昵称** —— 而这些正是 ASR 最常出错的词。

**最小编辑能力集（P0）**：

| 能力 | 说明 |
| --- | --- |
| 句列表查看 | 时间 + 文本，点击跳转播放该句 |
| 文本编辑 | 单句双击就地编辑（保存即更新文件与句子表） |
| 时间微调 | 单句起止时间 ±0.1s 微调（键盘方向键） |
| **整体偏移** | ±0.1s ~ ±5s 整体平移（ASR 常见系统偏差，一键修正全片） |
| 合并 / 拆分句 | 两句合并、一句按光标拆开（ASR 断句不理想时） |
| 撤销 | 至少支持"整体偏移"的撤销（偏移是全局操作，改错代价大） |

**P1 增强**：查找替换（批量改人名）、按语言并排对照（原文 + 译文双栏检查）。

**导出/导入**：编辑后可重新导出（覆盖原文件）；也支持**导入外部字幕文件**（S7）。

### S7 外部字幕导入

**【修正建议 —— 原需求未提，但"外挂"的本义就是可替换】**：
许多用户手里已经有字幕（自己做的、下载的、其他工具产出的）。

- 上传 `.srt` / `.vtt` → 解析 → 建一条 `source='import'` 的轨（**不跑 ASR**）；
- 同名语言存在 ASR 轨时，导入轨**优先**（UI 标注"外部导入"，可切换）；
- 校验：格式解析失败 → 400 + 行号定位；时间轴与视频时长不匹配 → 警告但允许（用户可能明知）；
- 上限：单文件 2 MB / 10000 句（防滥用）。

### S8 搜索集成

**原需求**：搜索时添加**可选的**根据字幕内容模糊查询。

**【保留】** + 【澄清】：

- **"可选"的落实**：搜索设置里一个独立开关「搜索包含字幕内容」（默认**开** —— 搜索价值高、成本低；
  关闭后字幕不进搜索结果）。
- **匹配方式**：与现有搜索范式对齐（`ILIKE '%q%'`）。是否叠加 `pg_trgm similarity() >= 0.15`
  → 建议**叠加**（字幕是长文本，模糊匹配能显著提升召回，如"火烧云"匹配"火红的云"）。
- **结果项**：与回忆同构 —— 缩略图 + 命中的文本片段（关键词高亮）+ 时间点 + 「跳转」按钮。
  点击 → `?t=<句起点ms>`（**复用回忆功能建立的路由契约**，不新建）。
- **排序**：字幕命中独立成组，不参与媒体的相关性排序（同回忆的设计，防淹没）。
- **性能**：句子表加 `pg_trgm` GIN 索引；检索限定 `LIMIT`；字幕表规模估算见 §10.2。

### S9 分享集成

**【修正建议 —— 默认不包含】**（同回忆 R-6/Q-6 的隐私立场，且字幕敏感度更高）：

| 场景 | 行为 |
| --- | --- |
| 视频分享 | 勾选项「附带字幕」→ 默认**不勾**；勾选后可选择**语言轨**（多选） |
| 相册分享 | 同上三级（不含 / 全部 / 自定义按视频） |
| 分享页播放 | 字幕可用（语言切换）+ 提供下载（若该分享开启了下载权限） |
| 未勾选时 | 分享页**完全不暴露字幕存在**（不显示空的语言按钮，避免"这里本来有东西"的暗示） |

**注意**：字幕文本会进入分享页 → 渲染必须走 `textContent`（纯文本），**禁止 HTML 注入**（与回忆 R-1 同一条安全纪律）。

### S10 字幕管理页

**【修正建议，P2】**：全局视图「所有已生成/待生成字幕的视频」：
- 列表：视频 + 语言轨数 + 状态（未生成 / 排队 / 识别中 / 已完成 / 失败）+ 时长 + 生成时间；
- 批量：批量触发、批量删除、按状态筛选；
- 价值：批量导入后一次性发起 ASR（手动触发的入口）。

## 4. 数据模型

### 4.1 新表（建议迁移编号在 `video_moments` 之后，实装时以实际链尾为准）

```sql
-- 字幕轨：一个视频 × 一种语言 × 一类来源 = 一轨
CREATE TABLE subtitle_tracks (
    id           UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    media_id     UUID NOT NULL REFERENCES media(id) ON DELETE CASCADE,
    owner_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,  -- 创建者（隔离依据）
    lang         VARCHAR(16) NOT NULL,        -- BCP-47：zh-Hans / en / ja / ru ...
    kind         VARCHAR(16) NOT NULL,        -- original | translated
    source       VARCHAR(16) NOT NULL,        -- asr | import | translate
    status       VARCHAR(16) NOT NULL DEFAULT 'pending',  -- pending|running|done|failed|skipped
    skip_reason  VARCHAR(32),                 -- no_audio | no_speech | too_long | too_short
    object_path  TEXT,                        -- MinIO：subtitles/<media_id>/<lang>.srt|.vtt
    cue_count    INTEGER,
    engine       VARCHAR(32),                 -- whisper.cpp
    model        VARCHAR(32),                 -- small / large-v3-turbo-q5_0 ...
    src_lang     VARCHAR(16),                 -- 翻译轨：来源原文轨的语言
    progress     REAL NOT NULL DEFAULT 0,     -- 0..1（长音频进度，供 UI 显示）
    error        TEXT,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (media_id, lang, kind)             -- 同语言同类型仅一轨（重跑=覆盖）
);

-- 字幕句子：搜索 / 编辑 / 统计的载体
CREATE TABLE subtitle_cues (
    id         BIGSERIAL PRIMARY KEY,
    track_id   UUID NOT NULL REFERENCES subtitle_tracks(id) ON DELETE CASCADE,
    media_id   UUID NOT NULL,                 -- 冗余：搜索直接命中 media，免 JOIN
    idx        INTEGER NOT NULL,              -- 句序（0 基）
    start_ms   BIGINT NOT NULL CHECK (start_ms >= 0),
    end_ms     BIGINT NOT NULL CHECK (end_ms > start_ms),
    text       TEXT NOT NULL,
    UNIQUE (track_id, idx)
);

CREATE INDEX idx_subcue_media   ON subtitle_cues (media_id, start_ms);
CREATE INDEX idx_subtrack_media ON subtitle_tracks (media_id);
CREATE INDEX idx_subtrack_owner ON subtitle_tracks (owner_id, created_at DESC);
-- 搜索：pg_trgm GIN（与现有搜索的 similarity() 范式同源；pg_trgm 应已启用）
-- CREATE INDEX idx_subcue_text ON subtitle_cues USING gin (text gin_trgm_ops);
```

**设计决策与理由**：

1. **轨与句分表**（决策）：轨是"文件级"元数据（语言、来源、状态、工程参数），句是"检索级"数据。
   搜索只需要 `subtitle_cues`；播放器只需要文件。职责清晰，索引各归其位。
2. **`UNIQUE(media_id, lang, kind)`**（决策）：同一语言同一类型只允许一轨 → 重跑即覆盖，
   避免"跑了三次生成三条中文轨"的脏数据。
3. **`status` 里含 `skipped`**（决策）：无音轨/无语音/过长等"不处理"的情况要有明确落点，
   否则 UI 无法解释"为什么这个视频没有字幕"，也会导致重复排队。
4. **`lang` 不做枚举**（决策）：whisper 支持 99 种语言，且用户可能导入任意语言字幕。
   用 BCP-47 字符串 + 应用层校验，扩展性最好（与 `media.media_type` 枚举的取舍理由相反 ——
   类型是有限封闭集，语言不是）。
5. **时间用毫秒 BIGINT**（决策）：与 `video_moments` 一致（`media.duration` 是秒，写入时换算）。

### 4.2 与 `video_moments` 的关系（重要）

**两套表，不合并**。理由：
- 语义不同：回忆是**稀疏标注**（一视频几条），字幕是**连续轨**（一视频几百上千句）；
- 生命周期不同：回忆由用户增删改，字幕由任务产出、可整轨重建；
- 查询模式不同：回忆按 `media_id` 取全部；字幕按语言轨取 + 全文检索。
强行合并会让两边都别扭（这是 `video_moments` 设计时"不复用 `memories` 表"的同一判断标准）。

### 4.3 `share_links` 扩展

```sql
-- 与 video_moments 的 moment_scope 并列，语义一致
ALTER TABLE share_links ADD COLUMN subtitle_scope JSONB NOT NULL DEFAULT '{"mode":"none"}';
-- {"mode":"none"} | {"mode":"all"} | {"mode":"selected","langs":["zh-Hans","en"]}
-- 相册分享：{"mode":"per_media","items":{"<media_id>":{"mode":"none"|"all","langs":[...]}}}
```

## 5. 交互与状态机

### 5.1 字幕轨状态机（服务端）

```
pending ──worker 拉取──> running ──成功──> done
   │                       │
   │                       └──失败（重试 ≤2 次）──> failed（可手动重试）
   │
   └──排队前拦截──> skipped（no_audio / no_speech / too_long / too_short）
```

- `running` 期间写 `progress`（whisper.cpp 的 stderr 有进度输出，用 `parser.go` 同款方式解析）；
- 取消：`q:subtitle` 的 waiting 项可移除（`internal/queue/control.go` 已有按载荷精确 LREM 的原子脚本）；
  **running 项取消 = 杀子进程 + 标记 failed(cancelled)**（ffmpeg/whisper 都是 subprocess，可 kill）。

### 5.2 详情页字幕块（UI 状态）

```
空态（未生成）
  └─[生成字幕]（总开关开启时）
       ├─ 排队中：显示"排队第 N 位"
       ├─ 识别中：进度条 + 百分比 + [取消]
       ├─ 完成：语言轨列表（原文 + 各翻译轨）
       └─ 失败：原因 + [重试]
轨列表态（已完成）
  ├─ 语言切换（用于播放器即时生效）
  ├─ [编辑]（打开句列表浮层，S6）
  ├─ [下载]（.srt / .vtt）
  ├─ [添加语言]（翻译轨按需生成，S3）
  └─ [导入字幕]（S7）
```

### 5.3 编辑浮层的就地编辑（S6）

```
句列表（虚拟滚动）
  行：[00:12 → 00:15] 「这句话的文本」        [跳转] [编辑]
  双击文本 → 就地变输入框 → 回车保存 / Esc 取消
  
时间微调：选中行后 ↑↓ 调 start，Shift+↑↓ 调 end（步长 0.1s）
整体偏移：顶部一条滑杆 ±5s，实时预览（列表时间全部位移），确认后落库 + 记录可撤销
合并/拆分：选中相邻两行 → 合并；光标处 → 拆分
```

### 5.4 播放器字幕显示（S5）

- 普通视频：控制条右侧新增字幕按钮（有轨时才显示）→ 弹出语言列表（含"关闭"）；
- 全景视频：同上，但字幕渲染在 canvas 之上的 DOM 层；
- **位置/字号/背景条**三项设置 → 存 `ui-prefs`（**全量 payload 纪律**：写入前先 GET 合并）。

## 6. 隔离 / 权限 / 接口

### 6.1 隔离（沿用唯一真源）

- 读写路径全部经 `internal/mediascope`；无权限 → **404 非 403**；
- `subtitle_tracks.owner_id` = 创建者（隔离依据），与 `video_moments` 同构；
- **共享空间**：成员可读（含播放字幕）；**编辑/删除/重跑** 仅创建者与空间管理者
  （与回忆 Q-3 裁决保持**同一条规则**，不另立标准）。

### 6.2 接口草案

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/media/:id/subtitles` | 轨列表（含状态/进度） | media 读 |
| POST | `/media/:id/subtitles` | 触发 ASR（body 可带 `lang` 指定源语言） | media 编辑权 + 总开关 + 配额 |
| POST | `/media/:id/subtitles/translate` | 生成翻译轨（body: `{langs:[...]}`） | 同上 |
| GET | `/subtitles/:trackId/file` | 下载/播放字幕文件（`.vtt` / `.srt`） | media 读（分享场景走 token 校验） |
| GET | `/subtitles/:trackId/cues` | 句列表（分页） | media 读 |
| PATCH | `/subtitles/:trackId/cues/:idx` | 编辑单句（文本/时间） | 创建者或管理者 |
| POST | `/subtitles/:trackId/cues/ops` | 批量操作（整体偏移/合并/拆分） | 创建者或管理者 |
| POST | `/media/:id/subtitles/import` | 导入外部字幕（multipart 或 JSON） | media 编辑权 |
| DELETE | `/subtitles/:trackId` | 删除轨 | 创建者或管理者 |
| POST | `/subtitles/:trackId/retry` | 失败重试 | 创建者或管理者 |
| GET | `/subtitles` | 管理页列表（分页 + 状态筛选） | 登录（按 mediascope 过滤） |

**审计**：触发/完成/失败/导入/删除/翻译生成 → 记录（**只记语言、时长、句数、耗时、状态**，
**严禁写入字幕文本内容** —— 详见 §6.4）。

### 6.3 搜索集成

`GET /search` 增加第三个结果集（字幕命中），返回 `{track_id, media_id, lang, start_ms, snippet}`；
是否包含由**用户偏好**（S8 开关）与服务端配置共同决定（服务端总开关关闭时，任何用户都搜不到）。

### 6.4 隐私（本功能特有的硬要求）

| 要求 | 落实 |
| --- | --- |
| 全本地推理 | whisper.cpp 本地跑，**音频不出机器**；翻译走用户自配的 LLM 上游（可选关闭） |
| 默认不外发 | 分享默认不包含字幕（S9）；搜索开关默认开但总开关关闭时全局失效 |
| 审计不含内容 | 审计 detail 只记元数据；**字幕文本不进审计、不进日志**（日志里只打句数） |
| 崩溃报告 | 不采集音频/文本；错误日志需过滤文本片段（whisper 的 stderr 可能含识别文本 → **只取进度行，丢弃内容行**） |
| 删除彻底 | 删除轨 → 级联删句子 + 删 MinIO 文件；删除视频 → CASCADE 全清 |

## 7. 边界与异常处理矩阵

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| SB-01 | 视频无音轨 | 排队前 ffprobe 拦截 → `skipped(no_audio)`，UI 显示"该视频没有音轨" |
| SB-02 | 纯音乐/无语音 | whisper 返回空 → `skipped(no_speech)`，保留记录防重跑 |
| SB-03 | 视频时长 > 上限（默认 60 分钟） | 拦截 + 提示 + 提供"仍然生成"的显式确认 |
| SB-04 | 视频时长 < 10 秒 | 跳过（`too_short`） |
| SB-05 | ASR 运行中服务重启 | `running` 且超过心跳时限的轨 → 标记 `failed(stale)`，可重试（对照 `transcode` 的 stale 处理） |
| SB-06 | 模型文件缺失 | 任务失败并给出**可操作的错误**（"模型未下载，运行 `make models` 或手动放置到 <路径>"），不是笼统 500 |
| SB-07 | 磁盘/MinIO 空间不足 | 写文件失败 → 任务失败并保留错误；中间 WAV 立即清理 |
| SB-08 | 翻译轨 LLM 不可用 | 部分失败可增量补（已翻译的句保留）；整体失败标 failed，不影响原文轨 |
| SB-09 | 导入的字幕时间超出视频时长 | 警告但允许（用户可能有意）；播放时超出部分自然不显示 |
| SB-10 | 导入格式非法 | 400 + 行号定位（`expected "-->" at line 42`） |
| SB-11 | 同一语言重复导入 | 覆盖确认（提示"已存在中文轨，将替换"） |
| SB-12 | 编辑并发（两人同改一句） | last-write-wins；`updated_at` 变化供前端刷新（与回忆同取舍，不做乐观锁） |
| SB-13 | 分享链接过期/密码错 | 字幕端点复用既有 `checkAccess` 语义（403） |
| SB-14 | 分享未勾选字幕 | 端点返回 404/空（**不暴露字幕存在**） |
| SB-15 | 全景视频字幕与陀螺仪/VR 冲突 | 字幕层固定在屏幕空间（不随视角转），位置可调（S5 三开关） |
| SB-16 | HLS 播放时字幕不同步（分片 seek 偏差） | 字幕按 `currentTime` 渲染，天然对齐；不做分片级处理 |
| SB-17 | 超长视频内存（whisper 分段处理） | 中间 WAV 用流式管道（ffmpeg stdout → whisper stdin）可选优化；MVP 先落地文件 |
| SB-18 | 用户关闭总开关但任务在跑 | 已入队任务继续（不中断用户已发起的操作），仅"不再新建" |
| SB-19 | `ui-prefs` 部分写入清掉其它偏好 | **禁止**：必须 GET 全量 → 合并 → PUT（项目既有坑，同回忆 B-21） |
| SB-20 | 字幕文本含 HTML/脚本注入 | 全链路 `textContent` 渲染 + 长度上限；导出文件转义控制字符（SRT/WTT 结构安全） |

## 8. ASR 引擎选型对比（重点章节）

### 8.1 候选方案

| 方案 | 许可 | 运行时 | 中文效果 | CPU 可用 | GPU | 输出字幕 | 与项目契合 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **A. whisper.cpp（推荐）** | **MIT** | 独立二进制（ggml） | 好（large-v3-turbo） | ✅ AVX/NEON | ✅ CUDA/Metal/Vulkan/ROCm | ✅ **原生 `-osrt`/`-ovtt`** | **高**：与「ffmpeg 仅 subprocess」同构；模型可挂载 |
| B. sherpa-onnx | Apache-2.0 | C++ 库 + Go 绑定（自带 ORT） | 好（Paraformer 中文优化） | ✅ | ✅ | 需自行拼装 | 中：引入**第二套 ORT**，与现有 `onnxruntime_go` 1.29.0 存在版本/符号冲突风险；静态库分发对多平台构建不友好 |
| C. faster-whisper | MIT | Python（CTranslate2） | 好 | ✅ | ✅ | 需自行拼装 | 低：**引入 Python 运行时**，与 Go 单栈不一致，镜像与部署复杂度上升 |
| D. 云 ASR API（DashScope/OpenAI 等） | 商用条款 | HTTP | 好 | — | — | 需自行拼装 | 低：**音频要上传到外部**，违背自托管与隐私前提（§6.4）。仅可作可选加速（用户自带 key），二期不做 |

### 8.2 为什么是 whisper.cpp

1. **许可最干净**：仓库 MIT + 模型 MIT，符合项目"许可二次确认"的纪律（对照 Redis→Valkey 的教训）。
2. **输出即所得**：`-osrt` / `-ovtt` 直接产出需求所指的"外挂字幕文件"，**不用自己拼装时间轴格式**
   （自研 SRT 生成看似简单，实则边界多：序号连续性、时间格式 `HH:MM:SS,mmm`、换行与转义）。
3. **零链接风险**：独立二进制 + subprocess，不进 CGO 链接闭包 → 不触碰 `backends-cgo` 的 ORT 版本约束
   （项目对 ORT 版本有严格钉死：`onnxruntime_go` 头文件与运行时必须同为 1.29.0）。
4. **CPU/GPU 双接口**：CPU 版二进制默认可用；CUDA 版为可选构建（`-DGGML_CUDA=ON`），
   配置项 `SUBTITLE_DEVICE=cpu|cuda|auto` 与 `FACE_DEVICE` / `EMBED_DEVICE` 完全同构 —— 直接命中项目红线。
5. **生态与可运维性**：whisper-cli 有稳定的 CLI 契约、量化模型可直接下载、社区验证充分
   （对比 sherpa-onnx 的 Go 绑定在交叉编译与版本跟进上的维护负担）。

### 8.3 模型选择与体积（**必须实机实测校准**）

| 模型 | 体积（FP16） | 量化可用 | 定位 | 建议 |
| --- | --- | --- | --- | --- |
| tiny | 75 MB | — | 极速、精度低 | 不推荐（中文错字多） |
| base | 142 MB | — | 快 | 仅低配设备备选 |
| **small** | **466 MB** | small-q5_1 | **CPU 默认** | ✅ **默认**（中文可用，速度可接受） |
| medium | 1.5 GB | medium-q5_0 | 质量更好、更慢 | CPU 上偏慢，谨慎 |
| **large-v3-turbo** | **1.5–1.6 GB** | **q5_0 ≈ 550 MB / q8_0 ≈ 800 MB** | **质量/速度最佳平衡** | ✅ **GPU 部署默认**（`large-v3-turbo-q5_0`） |
| large-v3 | 3.1 GB | q5_0 ≈ 1.1 GB | 最高质量 | 仅在质量优先、有 GPU 时 |

⚠️ **关于速度的诚实说明（核实所得）**：广为流传的"turbo 比 large-v3 快 8 倍"是 **OpenAI 在 A100 上用
PyTorch 实测的英文数据**，**不能迁移到 whisper.cpp 的 CPU/GPU 构建**（whisper.cpp 官方未发布对比）。
可用的经验规律是：**GPU 转写是"若干倍实时"，CPU 转写是"实时的小倍数"**。
**落地前必须在目标硬件上用真实样本实测**（whisper.cpp 自带 `whisper-bench`），
并据此校准 §10.2 的吞吐假设 —— 这与项目"不做无测量的断言"的纪律一致。

### 8.4 翻译（多语言轨）方案

| 方案 | 成本 | 质量 | 建议 |
| --- | --- | --- | --- |
| **复用 `/agent/llm/v1`（LLM 上游）** | 按 token 计；1 小时视频 ≈ 1 万汉字 ≈ 单语言 3–5k token | 好（上下文窗口可给） | ✅ **默认**（与回忆 L2 同源，复用配置/代理/审计） |
| 专用翻译 API（DeepL 等） | 按字符计 | 很好（但中文→小语种支持参差） | 可选（用户自带 key） |
| 本地 MT 模型（opus-mt ONNX） | 0 token | 一般 | 不推荐二期做（多一套模型体系，收益不匹配） |

**成本示例（重要）**：100 个视频 × 平均 30 分钟 ≈ 每个 1 万汉字 ≈ 1 万 token 输入 + 1 万输出（含 prompt）。
- 只出原文轨：**0 翻译成本**（ASR 本地免费）；
- +1 种语言：约 200 万 token；
- +5 种语言：约 1000 万 token —— **这就是"默认只出原文轨"的原因**。
**配额建议**：单日翻译句数上限（默认 3000 句/日），超出排到次日。

## 10. 埋点与性能

### 10.1 埋点（只记指标，不含内容）

| 事件 | 字段 |
| --- | --- |
| `subtitle.gen` | 触发方式 / 视频时长 / 模型 / 设备（cpu/cuda）/ 耗时 / 实时倍率（RTF）/ 结果状态 |
| `subtitle.edit` | 编辑类型（文本/时间/偏移/合并）/ 次数 |
| `subtitle.import` | 格式 / 句数 / 失败原因 |
| `subtitle.translate` | 目标语言 / 句数 / 失败率 / 耗时 |
| `subtitle.search` | 命中数 / 点击跳转率 |
| `subtitle.skip` | skip_reason 分布 |

**关键指标**：**RTF（实时倍率）= 视频时长 ÷ 识别耗时** —— 这是"要不要给更多机器/换模型"的唯一判据，
与回忆的 `ai_confirm` 采纳率同理，必须埋。

### 10.2 性能与容量

| 项 | 估算 | 说明 |
| --- | --- | --- |
| 句表规模 | 1 小时视频 ≈ 700–1100 句 | 1000 个视频 ≈ 100 万句 → PG 轻松承载；trgm 索引足够 |
| 字幕文件 | 1 小时 ≈ 30–60 KB/轨 | 可忽略 |
| 中间 WAV | 1 小时 ≈ 115 MB（16k/mono/16bit） | **用完即删**；峰值占用 = 并发数 × 时长 |
| ASR 吞吐 | CPU small：**实时的小倍数**（需实测）；GPU turbo：**若干倍实时** | 见 §8.3 诚实说明；**不写死数字** |
| 队列并发 | **1**（全局） | 与转码/索引/人脸错峰；闲时段优先 |
| 进度上报 | whisper 的 stderr 进度行 | 只取进度行（丢弃文本行，见 §6.4） |
| 编辑页性能 | 1000 句需虚拟滚动 | 复用现有 RecycleScroller 范式 |
