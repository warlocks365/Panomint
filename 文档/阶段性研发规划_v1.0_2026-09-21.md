## 二、问题分析：延期原因与主要瓶颈

### 2.1 事实校准（先纠正"慢"的参照系）

本周末（9/19–9/21）交付 **56 个提交、10+ 个 Job**：门禁 trio、MinIO 可选化、管理后台 UI、分享下载、独立部署实测、SSO、WebDAV、@eaDir 复用、CI 质量门、颜色/拆分债五批。**功能计划已 100% 覆盖，当前剩余的是工程债与外部阻塞项**——慢的感觉主要来自"每件事都要完整的验证闭环"。

### 2.2 五大瓶颈（按时间损耗排序）

| 瓶颈 | 表现 | 占比估测 | 对策 |
|---|---|---|---|
| **B1 网络环境税** | SSH 的 SFTP/exec 通道分钟级独立抖动；GitHub push 间歇失败（单晚重试 10~25 次）；大文件传输被迫走分块/workaround | 每次任务 20–40% | 已沉淀 4 套绕法（upload_chunks/docker-run-d/dl_chunks/服务器自建）；**治本需用户侧网络排查**（见 §5.3） |
| **B2 验证闭环成本** | 项目铁律"源码已验证≠线上已生效"：每改动 = 构建+部署+e2e 证据，单次闭环 15–30 分钟 | 每个任务固定 30 分钟左右 | 已压缩（容器化链/并发/守卫前置），再压需放宽验证纪律（**不建议**） |
| **B3 外部输入阻塞** | 3 项挂起全等用户侧输入（gh 认证/群晖样本/IdP 决策） | 不耗 AI 时间但挂账 | 见 §5.3 一次性清单 |
| **B4 剩余债的难度梯度** | 已拆的都是 400–700 行的"简单件"；剩 13 个全是 300–965 行的硬核（MapView 965 地图逻辑/360Player 725 引擎脚本/MediaViewer 683 查看器），单文件成本更高、风险更大 | 越往后越慢 | 阶段化拆解 + 风险递进（先低风险大件） |
| **B5 范围增长** | 9/20 用户裁决新增 052/053/054 三项产品功能（已完成）+041 解挂，计划外但合理 | 约 1.5 天 | 已收口；后续新增走规划评审 |

### 2.3 非瓶颈（明确排除）

- 模型/AI 能力、技术方案不确定性、需求不清——均不存在；所有延期项都有清晰路径。
- 代码质量/返工率——守卫+行为回归把返工压到了接近零（本周末零回滚）。

## 四、阶段划分与可衡量交付

### Phase 1｜低风险大件清债（9/21–9/24，3 天）

**范围**：SpacesView 382 → FoldersView 377 → ShareCreateDialog 313 → TimelineGrid 495 → PlayerView 511 → MapTimeline 528（6 件，模板驱动、行为回归覆盖好）。

**交付标准（可衡量）**：
- org 守卫超大文件 13 → **7**；新文件全部 ≤300 行
- 每文件一次部署 + 对应页面行为探针 PASS（范式沿用本周末已验证的五批拆法）
- 颜色残余捎带清零（MapTimeline stat-dots 4 处 + 单发）

**风险**：MapTimeline 涉地图栈，回归用服上 verifyMap* 脚本族。

### Phase 2｜硬核攻坚（9/25–9/29，4~5 天）

**范围**：AlbumDetailView 578 → PeopleView 587 → MediaViewer 683 → SharePublicView 735 → MediaInfoPanel 905 → 360Player 725 → MapView 965（7 件，按风险递进；360Player/MapView 放最后因其逻辑密度最高）。

**交付标准**：
- org 守卫超大文件 7 → **0**（基线 refresh 后清单为空）
- 每个文件：拆分 + 样式逐字迁移 + 该页面 e2e/截图比对 + 守卫全绿
- MapView/360Player 两件各配一次完整页面截图前后比对（像素级）

**风险与对策**：360Player 的 610 行脚本（Three.js/WebXR/陀螺仪）是最大不确定点——若拆到风险不可控，**允许登记"豁免拆分"**（守卫支持逐文件豁免清单），不硬拆。

### Phase 3｜挂起项闭环与 RC 就绪（9/30–10/2）

**范围**：应用密码 UI；Windows 挂载实测；用户输入到位后的 3 项复核（CI run / sidecar 样本解析 / IdP e2e）。

**交付标准**：
- 挂起项 8 项清单 → **0**（或每项都有用户签字的书面豁免）
- CI 全绿（含远端首跑复核）
- README/独立部署指南/契约 v1.3 与代码现状对账一致
- 打 `v0.9.0-rc1` 标签，产出 Release Notes 草稿

### Phase 4｜RC 稳定与发布准备（10/3–10/5）

**范围**：全量回归（守卫三件套 + verify 脚本族 + ops_check 一周巡检无告警）；修 RC 暴露的问题；发布决策呈报（用户拍板是否对外发布/如何发布）。

**交付标准**：回归全绿 + 发布建议书。

## 五、跟进机制

### 5.1 节奏（建议）

| 机制 | 频率 | 内容 | 载体 |
|---|---|---|---|
| 台账纪律 | 每 Job 即时 | 登记簿 §27.2 落账（目标/状态/证据三要素） | 仓库文档（已运行 58 Job） |
| 阶段门禁 | 每 Phase 结束 | 对照 §4 交付标准逐项核验，未达标不进下一阶段 | 规划文档勾选 + 提交证据 |
| 周复盘 | 每周日 20:00 | 进度 vs 规划、瓶颈复核、下周计划修订 | **建议设自动化**（见 5.3-④） |
| 阻塞上报 | 即时 | 硬阻断清单规则：3 次重试失败/需用户输入/破坏性操作 | 对话内即时呈报（现行） |

### 5.2 进度度量（看板数字）

每周复盘固定看 6 个数：① org 超大文件数 ② p0 颜色基线 ③ 挂起项数 ④ CI 状态 ⑤ 本周期提交数/Job 数 ⑥ 网络环境税耗时（自评）。

### 5.3 需要用户侧配合的事项（一次性清单）

| # | 事项 | 解锁什么 | 耗时 |
|---|---|---|---|
| ① | `gh auth login`（或提供 GH_TOKEN） | CI 远端 run 复核 | 2 分钟 |
| ② | 从群晖任拷一个 `@eaDir/<文件名>/` 目录给我 | sidecar 元数据迁移开工 | 5 分钟 |
| ③ | 决策：是否部署 Keycloak/Authelia 测 SSO（或不测、登记豁免） | SSO 真实 e2e | 决策即可 |
| ④ | 批准设立每周日复盘自动化（到点自动汇总 5.2 六数字并呈报） | 跟进机制自动化 | 一句话 |
| ⑤ | （可选）排查本机↔192.168.1.115 链路抖动（路由器/网线/网卡节能） | 砍掉 B1 网络税 | 用户方便时 |
